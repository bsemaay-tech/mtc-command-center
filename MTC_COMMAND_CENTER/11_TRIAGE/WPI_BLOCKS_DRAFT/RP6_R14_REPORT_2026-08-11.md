## Per-finding disposition

### F1 (HIGH) — function-definition recognition was not complete — UPHELD, CLOSED

**Reproduced.** The round-13 tokenizer recorded a `FUNCDEF` only when the
candidate name was followed by the parenthesised declarator. `function NAME
<compound>` — a valid bash definition — produced no record at all, so its name
never reached assertion 15's builtin/tool shadow counts. Two mutants make the
consequence executable, and both are certified rc 0 / `result=PASS` by the
published round-13 fence:

| Mutant | What round 13 reports | What bash does |
|---|---|---|
| `function printf { :; }` | `ASSERT_MET no_wrapper_shadow … builtin_shadow=0`, rc 0, PASS | the direct ERR-trap emitter prints nothing — `EXEC_[funckw]` records empty output for a `P0_STOP` line |
| `function command { :; }` | `ASSERT_MET no_wrapper_shadow … builtin_shadow=0`, rc 0, PASS | `command -v stat` returns the function's value — `EXEC_[prefixkw]` records `/attacker/stat`, and `command -v "$t"` is how the block resolves every tool |

The second is the audit's Pattern-11 overlay made concrete: `prefix_classify`
strips `command`/`builtin`/`exec` on the premise that the word resolves to the
builtin, and round 13 could not see the definition that falsifies the premise.

**Repair — completeness plus conservation, not one or the other.**

1. The tokenizer models the `function` reserved word: the word after it IS the
   definition name, with or without the declarator, recorded as
   `FUNCDEF … form=keyword` (the parenthesised shape is `form=paren`). It is
   recorded before every reserved-word and assignment rule, because after
   `function` bash is no longer at a command position.
2. Shapes it cannot read are `UNMODELED`, not reclassified: `function` followed
   by an operator or ending the input (`function_keyword_without_name`), and a
   word at command position followed by `(` without the matching `)`
   (`funcdef_declarator_unmodeled`). Both were driven and both produce the record.
3. **Assertion 16** requires a raw, line-oriented, deliberately over-broad
   definition census — independent of the tokenizer — and the `FUNCDEF` record
   set to name the **same lines**, compared with `cmp`. That is exactly one
   disposition per definition. It is the two-mechanism discipline assertion 11
   already applies to emitter sites, applied to the definition inventory that
   assertions 14 and 15 stand on.
4. The three prefix words are bound explicitly by name: assertion 15 now reports
   `prefix_shadow=` alongside `builtin_shadow=` and fails on either.

Nine definition shapes were driven through the repaired tokenizer, including
`function f` + newline + `{`, `g()` + newline + `{`, and the subshell-body forms
`function h() ( : )` and `i() ( : )`. All nine produce exactly one `FUNCDEF`, and
the raw census names the same nine lines. On the real block: 26 definitions, 26
`FUNCDEF` records, 26 raw census lines, `paren_form=26 keyword_form=0`.

own D026 mutant `toolshadow`, whose hard-coded `stat` name no longer kills

breaks is not a fence that caught the block, and the partial case — where the

The rewrite is value-preserving and that is asserted, not assumed: `readonly
NAME="…"` assigns exactly what `NAME="…"` assigns, so the mutated block resolves
the same twelve tools at run time and only the extractor stops reading them
(`EXEC_[invpartial]_readonly_assignment_is_value_preserving`).

**Repair — assertion 17, a conservation chain with no branch that can end in
`0`:**

1. Each declared inventory half (`P0_RP7_RO_TOOLS`, `P0_P0_ONLY_TOOLS`) must be
   assigned **exactly once** in a non-comment line, and the extractor's pattern
   must match **that same line**. A half assigned in a shape the extractor cannot
   read is `inventory_half_unextracted`; a half assigned twice is
   `inventory_half_assignments`.
2. The variable the block CONSUMES (`P0_RO_TOOLS` — the one the resolution loop
   iterates) must be assigned exactly once and composed from **exactly** the two
   declared halves, by reference-set equality. A third half that never reaches
   the composition is not the inventory this block resolves; one that does is
   seen.
3. No member may be dropped by the extractor's name grammar
   (`inventory_member_unmodeled`), none may be duplicated
   (`inventory_member_duplicated`), and the set may not be empty
   (`inventory_empty`).
4. Every DECLARED runtime handle is bound to a tool name **derived from the
   block's own bytes** — the `NAME="$P0_LOOKUP"` assignment and the
   `p0_lookup "$P0_TOOLS_RESOLVED" <tool>` site that precedes it — and that tool
   must be a member of the extracted set. A handle whose resolution site cannot
   be read is `handle_tool_underived`, which fails; it is not skipped. On the
   real block this derives, mechanically: `P0_STAT=stat P0_READLINK=readlink
   P0_ID=id P0_GETENT=getent P0_ENV=env rl=readlink`. With an empty or partial
   set, these bindings cannot be satisfied — which is what makes the empty
   universe unreachable rather than merely unlikely.
5. The `if [ -s tools ]` branch that assigned `n_sht=0` is gone. With an empty
   set the count is `UNDEFINED_EMPTY_INVENTORY`, which is not `0`, does not
   compare equal to it, and cannot be misread in a transcript.

### F3 (HIGH) — alias absence was lexical, not semantic — UPHELD, CLOSED

**Reproduced, with both evasions executed.** The round-13 check was a text search
for `expand_aliases` and one literal alias-definition spelling. Two mutants
defeat it and both are certified rc 0 / `result=PASS` by the round-13 fence:

- `P0_R14_AOPT=expand_` … `shopt -s "${P0_R14_AOPT}aliases"` — bash reports
  `shopt -q expand_aliases` **enabled**, and the string `expand_aliases` appears
  nowhere in the source (`EXEC_[aliasopt]` asserts both).
- `P0_R14_ANAME=p0_probe_kind` … `alias "${P0_R14_ANAME}"='…'` — the round-13
  pattern needs a literal identifier before the `=`. Driven end to end, the alias
  really replaces an otherwise admitted bare word: `EXEC_[aliasdef]` records
  `HIJACKED`.

**Repair — classify the operands, not the text.** The tokenizer now recognises
the `alias` builtin at the command position bash would resolve, which reaches it
through the `command`/`builtin` prefix strip and inside command substitutions
(both driven), and applies a fail-closed operand grammar to `shopt`: an option it
does not model (`shopt_option_unmodeled`), and **any** operand carrying an
expansion or an escape (`shopt_operand_unmodeled`), is `UNMODELED` — because a
constructed operand can name `expand_aliases` at run time while no lexical search
can see it. A literal `expand_aliases` operand is recorded whatever option
precedes it. `eval`, `source` and `.` were already `UNMODELED` command words, so
the indirect introduction routes were already closed. The round-13 lexical check
is **carried unchanged and still runs first**: either half alone is fail-open.
