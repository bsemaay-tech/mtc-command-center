## Finding 1 (HIGH) — the census missed constructed command words. UPHELD, CLOSED.

### The finding, restated and reproduced

`SELF_QA_RP6.md:6847-6856` searched each line for the CONTIGUOUS text
`p0_stop`/`p0_fail` or the contiguous `P0_STOP`/`P0_FAIL` literal. A shell
command word need not contain its own name contiguously. The audit inserted after
`p0_probe_kind() {`:

```bash
[ -z "${P0_R11_CMDQUOTE_MUTANT:-}" ] || p0_s""top "r11_cmdquote detail=quoted_command_word"
```

This session reproduced every element of that counterexample mechanically, inside
the published `R12_F1_RED` fence rather than by hand:

```text
M_[cmdquote]_is_valid_shell                     got=[syntax_ok]
EXEC_[cmdquote]_rc                              got=[3]
EXEC_[cmdquote]_emitted_line                    got=[P0_STOP reason=r11_cmdquote detail=quoted_command_word]
RED_[cmdquote]_r11_fence_certifies_the_mutant   got=[0]
RED_[cmdquote]_r11_census_is_blind              got=[emitter_lines=163 unmodeled=0]
```

The emission proof drives the **block's own** `p0_stop`/`p0_fail` wrappers and
its **own real** `p0_probe_kind`, extracted from the mutated bytes — not a
paraphrase of them. Catalogue pattern 12, confirmed.

The audit's diagnosis is accepted in full, and one thing is worth stating plainly
because it decided the shape of the repair: round 11 was not unlucky in its
choice of regex. A line-oriented text search cannot be fail-closed about command
words at all, because it has no model of what a command word is. Widening the
pattern would have produced the same class of finding in round 13.

### The repair

`R12_GRAMMAR` **supersedes** `R11_GRAMMAR`. It carries all eight round-11
assertions and all seven round-11 mutants forward **unchanged**, so nothing the
old fence killed is now survivable, and puts a real tokenizer in front of the
grep. The tokenizer:

- tracks quote state (`'…'`, `"…"`, `$'…'`), resolves backslash escapes, and
  **joins line continuations**, so it sees the word the shell sees;
- collapses every expansion (`$name`, `${…}`, `$(…)`, `$((…))`) to one sentinel
  byte, and **recurses into every `$( )`** as its own command context, and into
  the `trap` action string (20 fragments are scanned on the current bytes: the
  main source plus 19 command substitutions);
- locates COMMAND POSITIONS — start of list, after `; & && || | ( ) newline` and
  after the reserved words — skipping assignment prefixes, redirection targets,
  fd prefixes, `case` pattern lists, `for` name/word lists, and function
  definition names.

Over that it applies an explicit **fail-closed source-style policy**: a command
word is admissible only as `BARE` (no quote, backslash or expansion), a single
complete `QUOTED_LITERAL`, or a whole-word `PURE_EXPANSION`. The first two make a
contiguous census sound, because the name is contiguous in the source. The third
is a runtime-valued name, and assertion 12 pins the set of variables allowed to
be invoked at all, so a new indirect invocation cannot enter silently. **Every
other command-word syntax is UNMODELED and the fence FAILS** — quoted splices,
backslash escapes, line-continuation splits, expansion/literal concatenation — as
is every construct the scanner does not model: here-document, backtick,
unterminated quote, `eval`, `source`/`.`, or a command substitution nested inside
a parameter expansion. Independently, **any word anywhere** whose normalized text
contains an emitter token its raw text does not contain contiguously is reported
as a splice, which covers a spliced payload handed to `trap`.

Four new assertions carry it (9–12), on top of the eight carried forward:

```text
ASSERT_MET tokenizer_no_unmodeled_syntax fragments=20
ASSERT_MET tokenizer_sites_match_derivation tokenizer_sites=163 derived_sites=163
ASSERT_MET tokenizer_and_census_same_lines lines=163
ASSERT_MET runtime_command_words_declared sites=16 distinct=6
```

Assertion 11 is the load-bearing one for this finding: the tokenizer's emitter
line set and the grep census's line set must be equal **line for line**, compared
with `cmp`, not equal in total. A site one mechanism sees and the other does not
is a failure rather than a silent difference.

### The property, stated to the letter — and the round-11 wording withdrawn

> Every command word in the block is BARE, a single complete QUOTED_LITERAL, or a
> whole-word PURE_EXPANSION drawn from the declared RO-tool handle set. For the
> first two the command name is contiguous in the source, so the emitter census is
> complete over them; for the third the name is a **runtime value the fence does
> not and cannot evaluate**, which is why the set of invocable variables is pinned
> instead of the value. Any other command-word syntax, and any construct the
> tokenizer does not model, makes the fence FAIL rather than pass silently.

The audit named two places that overstated this. Both are handled, and the
difference in treatment is deliberate:

- **`STATUS_RP6_P0.md:20-21`** — writable and in scope. The sentence "coverage is
  censused by a broader independent rule that FAILS CLOSED on any emitter syntax

  corrected the same way; its second half stands and is still a residual.
- **`RP6_R11_REPORT_2026-08-11.md:86-90`** — a delivered audit-round report,
  which records what that round claimed, and not in this round's scope fence.
  **Corrected here rather than rewritten**, the same treatment round 11 gave the

  models no words, which is exactly why `p0_s""top` escaped it. The completeness
  claim attached to that rule in the round-11 report is **withdrawn** and
  replaced by the statement above.

### What the repair does NOT buy — stated, not implied

- It does not make the DERIVATION understand new syntax. The derivation still
  reads `p0_stop "…"`. `R12_F1_RED`'s last case asserts this rather than leaving
  it to the reader:
  `BOUNDARY_r12_parser_alone_still_blind_tokenizer_is_what_catches_it got=[invariant]`.
  The next round cannot mistake the tokenizer's reach for the parser's.
- It is a **static source** fence. It cannot constrain what a `<name>` class, or
  a declared tool handle, evaluates to at run time. Assertion 12 pins **which**
  variables may be invoked, not **what** they hold.
- Its tokenizer models the shell dialect this block is written in. Failing closed
  is a refusal to certify what it does not model; it is not a proof of
  equivalence to bash's own parser. `shellcheck` is not installed in this
  environment and was not run.
- `R11_GRAMMAR` is superseded, not broken: re-run against the round-12 bytes it
  still returns **rc 0**, `cases=15 pass=15 fail=0`. It is insufficient, which is
  a different thing, and it stays in the file because `R11_F1_RED` and
  `R12_F1_RED` both extract from it.
