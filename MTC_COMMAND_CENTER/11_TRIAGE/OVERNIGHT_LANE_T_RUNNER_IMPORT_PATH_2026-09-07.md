## Defect

`MTC_COMMAND_CENTER/11_TRIAGE/overnight_orchestrator.py::write_runner_extension` emits a runner
that:
1. sets `ROOT = Path(__file__).resolve().parent.parent / "04_PYTHON_PROTOTYPES"` (the prototypes
   directory itself), then
2. inserts `ROOT.parent` (the tools dir's parent, `03_QUANTLENS`) onto `sys.path`, then
3. emits `from PYTHON_PROTOTYPES import <id>_prototype` for each of the 19 `CANDIDATES`.

`PYTHON_PROTOTYPES` is not an importable package name — the directory on disk is literally
`04_PYTHON_PROTOTYPES` (digits-prefixed, no `__init__.py`) and nothing named `PYTHON_PROTOTYPES`
exists anywhere under `03_QUANTLENS`. Every one of the 19 import lines can never resolve; the
generated runner compiles (valid Python) but fails at import time if it were ever launched. The
`from mega_walk_forward import main` line beneath it works only by accident of the runner living
next to `mega_walk_forward.py` in the tools dir (Python auto-prepends the running script's own
directory to `sys.path[0]`) — that mechanism is untouched by this fix and out of scope.

## Fix (minimal diff)

`MTC_COMMAND_CENTER/11_TRIAGE/overnight_orchestrator.py`, `write_runner_extension`:

```diff
     imports = "\n        ".join(
-        f"from PYTHON_PROTOTYPES import {c.id}_prototype  # noqa: F401"
+        f"import {c.id}_prototype  # noqa: F401"
         for c in CANDIDATES
     )
@@
         ROOT = Path(__file__).resolve().parent.parent / "04_PYTHON_PROTOTYPES"
-        sys.path.insert(0, str(ROOT.parent))
+        sys.path.insert(0, str(ROOT))
```

`sys.path` now gets the prototypes directory itself (`ROOT`), so each `<id>_prototype` module is
importable directly by its bare module name — no package qualifier needed, matching how
`mega_walk_forward.STRATEGY_LIB` already scans `04_PYTHON_PROTOTYPES` for `*_prototype.py` files.
The lane-B indent join (`"\n        ".join(...)`) is untouched — only the string each line renders
changed, not the join. The `# 04_PYTHON_PROTOTYPES` references in the docstring/comments at
lines 585 and 591 are correct as-is (that is the real directory name) and were left alone.

Everything else in the module is byte-identical. The committed artifact was regenerated by
importing `overnight_orchestrator.py` as a module (`sys.path` insert of `11_TRIAGE`, module name
`overnight_orchestrator`) and calling `write_runner_extension(True)` with the module's own default
`TOOLS_DIR` (`03_QUANTLENS/tools`, per lane H). `main()` was never called; no argparse, no
orchestrator dry-run/apply prints.

## New regression test

`MTC_COMMAND_CENTER/11_TRIAGE/test_overnight_orchestrator_runner.py` — loads
`overnight_orchestrator.py` as a module, regenerates the runner into `tmp_path` (monkeypatching
`TOOLS_DIR`, never the real tools dir), and asserts:
1. the emitted file `py_compile`s;
2. no `from PYTHON_PROTOTYPES import ...` / `import PYTHON_PROTOTYPES` line remains (the
   substring `PYTHON_PROTOTYPES` legitimately still appears in the `ROOT = ...` path literal and
   in a trailing comment — the assertion targets the specific bad import statement, not the bare
   substring);
3. `sys.path.insert(0, str(ROOT))` is present and `sys.path.insert(0, str(ROOT.parent))` is not;
4. every emitted import line is a bare `import <id>_prototype` (via `ast`), in `CANDIDATES` order,
   with the lane-B 8-space indent join intact (no leading whitespace after `dedent`);
5. every `CANDIDATES` id has a matching `<id>_prototype.py` file under `PROTO_DIR` (fails loudly
   naming any id that doesn't, rather than assuming one exists);
6. `importlib.util.find_spec` locates every `<id>_prototype` module with `PROTO_DIR` prepended to
   `sys.path` (static — no prototype is imported/executed).
