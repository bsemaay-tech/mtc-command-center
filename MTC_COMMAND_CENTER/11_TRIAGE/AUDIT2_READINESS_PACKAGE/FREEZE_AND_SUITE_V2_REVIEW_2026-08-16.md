### F5 trace and cardinality reachability

The intended trace is:

1. Capture manifest/root supplied in the adopted kickoff. `MTC_COMMAND_CENTER/11_TRIAGE/AUDIT2_READINESS_PACKAGE/FREEZE_PROCEDURES_V2_2026-08-15.md:591-607`
2. `WPA_COMPLETED` in the event ledger supplies `capture_id`, `artifact_id`, and `tested_sha`. `MTC_COMMAND_CENTER/11_TRIAGE/AUDIT2_READINESS_PACKAGE/FREEZE_PROCEDURES_V2_2026-08-15.md:774-780`
3. Those three fields select artifact-index rows; exactly one Git row and one raw row are required. `MTC_COMMAND_CENTER/11_TRIAGE/AUDIT2_READINESS_PACKAGE/FREEZE_PROCEDURES_V2_2026-08-15.md:782-800`
4. The source lines are preserved and compared with final Git-object and raw identities. `MTC_COMMAND_CENTER/11_TRIAGE/AUDIT2_READINESS_PACKAGE/FREEZE_PROCEDURES_V2_2026-08-15.md:801-825`

The isolated cardinality predicate is real: zero selected rows makes `selected=0/git=0/raw=0` and stops; two Git plus one raw makes `selected=3/git=2/raw=1` and stops. The integrated procedure still has an earlier reachability defect. `$WpaCaptureManifest` is specified as being inside `$WpaCaptureRoot`, while the exact-set enumeration includes every file under that root and compares it with the manifest rows. `MTC_COMMAND_CENTER/11_TRIAGE/AUDIT2_READINESS_PACKAGE/FREEZE_PROCEDURES_V2_2026-08-15.md:602-604`; `MTC_COMMAND_CENTER/11_TRIAGE/AUDIT2_READINESS_PACKAGE/FREEZE_PROCEDURES_V2_2026-08-15.md:750-772` A manifest inside that root must therefore list and hash itself to avoid being an extra member, but no self-identity construction is defined. In the ordinary realizable layout, the exact-set gate stops before the zero/multiple selector can run. Put the manifest outside the enumerated root or define a non-self-referential detached-root scheme, then retain the cardinality branch.
