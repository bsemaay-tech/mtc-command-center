## 1. Network contract

### Required end state

1. The bridge control listener binds to **exactly `127.0.0.1:8790`**. No bind on `0.0.0.0`, `::`, `::1`, a public/private interface address, or any other port satisfies this contract; the governing task explicitly stops on any non-loopback 8790 exposure, while the blueprint narrows the allowed bind to the single IPv4 endpoint (`MTC_COMMAND_CENTER/11_TRIAGE/KVM2_AI_LAB_AND_BRIDGE_EXECUTION_TASKS_2026-07-25.md:119-130`; `MTC_COMMAND_CENTER/11_TRIAGE/KVM2_PROGRAM/boundaries/NETWORK_AND_SERVICE.md:3-11`).
2. Operator access to 8790 is **only through an owner-authorized SSH local-forward tunnel**, using the shape `ssh -N -L 8790:127.0.0.1:8790 <operator ssh alias>`; port 8790 is never published, reverse-proxied, or added to UFW (`IBKR_PAPER_BRIDGE/deploy/linux/COMMANDS.md:230-236`).
3. UFW is active, defaults to deny incoming traffic, and permits inbound SSH only on port 22 / the `OpenSSH` profile. Any other `ALLOW IN` target fails closed, and any UFW mention of 8790 fails closed (`IBKR_PAPER_BRIDGE/deploy/linux/lib/common.sh:150-178`).
4. The install and verification assets may **read and assert** firewall state but may not add, delete, or change a firewall rule (`MTC_COMMAND_CENTER/11_TRIAGE/KVM2_PROGRAM/boundaries/NETWORK_AND_SERVICE.md:5-9`; `IBKR_PAPER_BRIDGE/deploy/linux/README.md:93-98`).
5. The frozen Phase-2 artifact contains a firewall manifest, listener inventory, loopback assertions, and hashes; those are required P2-04 evidence, not optional commentary (`MTC_COMMAND_CENTER/11_TRIAGE/KVM2_AI_LAB_AND_BRIDGE_EXECUTION_TASKS_2026-07-25.md:119-127`).
6. Loopback is not treated as same-host process isolation. Lab admission remains blocked until a separate OS-enforced isolation design and denial suite is accepted (`MTC_COMMAND_CENTER/11_TRIAGE/KVM2_PROGRAM/boundaries/NETWORK_AND_SERVICE.md:9-11`; `IBKR_PAPER_BRIDGE/deploy/linux/README.md:133-135`).

### Verification contract

Verification is evidence capture for a later separately authorized gate; none of it is executed by this draft.

1. **Static, candidate-bound:** record the exact candidate SHA; hash the firewall manifest, listener inventory, network blueprint, rendered unit, and verifier; prove the accepted source names `127.0.0.1:8790` and contains no wildcard/non-loopback bind. The P2-04 contract requires the inventories/assertions/hashes, and the Gate-A candidate's helper implements a fail-closed exact-bind source check (`MTC_COMMAND_CENTER/11_TRIAGE/KVM2_AI_LAB_AND_BRIDGE_EXECUTION_TASKS_2026-07-25.md:119-130`; `2ce41e34:IBKR_PAPER_BRIDGE/deploy/linux/lib/common.sh:183-190`).
2. **Installed but masked/unstarted:** run the candidate-bound read-only verifier without suppressing failures. It must prove no bridge process, a completely closed control port, no public listener, and UFW active/default-deny/SSH-only (`IBKR_PAPER_BRIDGE/deploy/linux/verify.sh:227-250`; `IBKR_PAPER_BRIDGE/deploy/linux/COMMANDS.md:224-228`).
3. **First authorized start:** capture one and only one `127.0.0.1:8790` listening socket, no non-loopback 8790 socket, `NRestarts=0`, and a loopback status response reporting DISARMED and TESTNET. The prescribed first-start evidence commands and expected results are recorded in the candidate command package (`2ce41e34:IBKR_PAPER_BRIDGE/deploy/linux/COMMANDS.md:214-221`).
4. **Tunnel-only reachability:** while the separately authorized SSH tunnel is active, reach the loopback service through that local forward; with the tunnel absent, direct remote access to 8790 must fail. Preserve the tunnel invocation, socket inventory, UFW output, and negative direct-access result without recording private host identifiers (`IBKR_PAPER_BRIDGE/deploy/linux/COMMANDS.md:230-236`; `MTC_COMMAND_CENTER/11_TRIAGE/KVM2_AI_LAB_AND_BRIDGE_EXECUTION_TASKS_2026-07-25.md:84-87`).
5. **No proxy/publication:** capture the relevant listener/firewall manifest and an explicit no-8790-proxy conclusion; the programme requires no public/non-loopback bind and no 8790 proxy (`MTC_COMMAND_CENTER/11_TRIAGE/KVM2_AI_LAB_AND_BRIDGE_EXECUTION_TASKS_2026-07-25.md:722-727`).

Current live KVM2 listener, UFW, SSH-tunnel, proxy, and reachability state: **UNKNOWN**. What settles it is a separately authorized, candidate-bound, read-only capture of the exact evidence above; Phase 1 names UFW and listening sockets as baseline evidence, and stops on any public non-SSH listener (`MTC_COMMAND_CENTER/11_TRIAGE/KVM2_AI_LAB_AND_BRIDGE_EXECUTION_TASKS_2026-07-25.md:76-90`).

### Violation signature

Any one of the following violates the network contract:

- any 8790 listener other than the single `127.0.0.1:8790` listener, including `0.0.0.0:8790`, `[::]:8790`, or `[::1]:8790` (`MTC_COMMAND_CENTER/11_TRIAGE/KVM2_PROGRAM/boundaries/NETWORK_AND_SERVICE.md:3-11`);
- UFW inactive, incoming default other than deny, any inbound allow other than port 22 / `OpenSSH`, or any rule mentioning 8790 (`IBKR_PAPER_BRIDGE/deploy/linux/lib/common.sh:153-178`);
- direct remote reachability of 8790, a published/container-forwarded 8790, a reverse proxy to 8790, or operator access not carried by the authorized SSH tunnel (`IBKR_PAPER_BRIDGE/deploy/linux/COMMANDS.md:230-236`);
- installer/verifier firewall mutation rather than read-only assertion (`IBKR_PAPER_BRIDGE/deploy/linux/README.md:93-98`);
- a missing/unhashed firewall manifest or listener inventory, or a static/runtime loopback assertion that is absent or does not match the frozen candidate (`MTC_COMMAND_CENTER/11_TRIAGE/KVM2_AI_LAB_AND_BRIDGE_EXECUTION_TASKS_2026-07-25.md:119-130`);
- claiming that loopback alone isolates the bridge from same-host lab processes (`IBKR_PAPER_BRIDGE/deploy/linux/README.md:133-135`).

### Out of scope

- Changing UFW, SSH, host networking, DNS, certificates, proxies, NAT, provider firewalls, or any listener is excluded; this is a design contract only (`MTC_COMMAND_CENTER/11_TRIAGE/KVM2_PROGRAM/boundaries/NETWORK_AND_SERVICE.md:3-11`).
- Per-destination egress control and same-host lab isolation are not solved here; current deployment assets explicitly defer destination egress control and keep AI-lab admission blocked on separate isolation work (`IBKR_PAPER_BRIDGE/deploy/linux/README.md:128-135`).
- No installation, tunnel opening, service start, host probe, public scan, TESTNET/mainnet contact, broker/exchange call, or firewall verification is authorized by this draft (`MTC_COMMAND_CENTER/11_TRIAGE/KVM2_AI_LAB_AND_BRIDGE_EXECUTION_TASKS_2026-07-25.md:8-12,265-284`).

## 2. Service contract

### Required end state

1. `mtc-bridge-first-start.service` is the only installer-delivered unit. It has no `[Install]` section, is installed masked, is neither started nor enabled by the installer, and binds its working directory and Python executable to one exact immutable release SHA (`MTC_COMMAND_CENTER/11_TRIAGE/KVM2_PROGRAM/boundaries/NETWORK_AND_SERVICE.md:13-23`; `2ce41e34:IBKR_PAPER_BRIDGE/deploy/linux/systemd/mtc-bridge-first-start.service.template:11-19,29-45`).
2. The first-start unit orders after and wants `network-online.target`, runs as the unprivileged `mtc-bridge:mtc-bridge` identity, and has no root or ambient capability path (`2ce41e34:IBKR_PAPER_BRIDGE/deploy/linux/systemd/mtc-bridge-first-start.service.template:21-34,63-89`).
3. Least privilege is fail-closed: `NoNewPrivileges=yes`, empty `CapabilityBoundingSet` and `AmbientCapabilities`, private temporary/device namespaces, strict system/home/proc/kernel/control-group protections, a system-service syscall filter, `UMask=0077`, and write access limited to `/var/lib/mtc-bridge` and `/var/log/mtc-bridge` (`2ce41e34:IBKR_PAPER_BRIDGE/deploy/linux/systemd/mtc-bridge-first-start.service.template:63-93`).
4. Graceful stop sends `SIGTERM`, uses `KillMode=mixed`, allows 45 seconds, and only then permits final `SIGKILL`; both Phase-2 service profiles carry this stop contract (`2ce41e34:IBKR_PAPER_BRIDGE/deploy/linux/systemd/mtc-bridge-first-start.service.template:47-52`; `MTC_COMMAND_CENTER/11_TRIAGE/KVM2_PROGRAM/boundaries/NETWORK_AND_SERVICE.md:25-27`).
5. The first start is DISARMED and TESTNET-only, exactly once, with no retry. Its unit pins `MTC_BRIDGE_START_MODE=credential_free_disarmed`, uses `Restart=no`, and retains start throttling keys without creating an automatic restart loop (`2ce41e34:IBKR_PAPER_BRIDGE/deploy/linux/systemd/mtc-bridge-first-start.service.template:21-27,36-56`; `MTC_COMMAND_CENTER/11_TRIAGE/KVM2_AI_LAB_AND_BRIDGE_EXECUTION_TASKS_2026-07-25.md:331-348`).
6. `mtc-bridge-steady.service` remains an inert, separate, unhashed-for-admission template: no script installs or enables it. Restart-enabled service is inadmissible until crash/kill/reboot fault injection proves DISARMED startup, reconciliation gating, state continuity, duplicate prevention, and throttling, followed by the required fresh acceptance and baseline hash (`2ce41e34:IBKR_PAPER_BRIDGE/deploy/linux/systemd/mtc-bridge-steady.service.template:3-20`; `MTC_COMMAND_CENTER/11_TRIAGE/KVM2_AI_LAB_AND_BRIDGE_EXECUTION_TASKS_2026-07-25.md:119-130`).
7. If a later gate admits the steady profile, its currently drafted bounded restart policy is `StartLimitIntervalSec=600`, `StartLimitBurst=3`, `Restart=on-failure`, and `RestartSec=30`; this is not first-start policy and is not admitted by this contract (`2ce41e34:IBKR_PAPER_BRIDGE/deploy/linux/systemd/mtc-bridge-steady.service.template:24-30,44-53`).
8. Persistent stdout/stderr belongs under `/var/log/mtc-bridge`; the frozen log policy rotates daily, retains 30 generations, rotates early at 64 MiB, delays compression by one generation, uses `copytruncate`, and recreates files as `0640 mtc-bridge:mtc-bridge` without restarting the service (`IBKR_PAPER_BRIDGE/deploy/linux/logrotate/mtc-bridge:1-26`).
9. The first-start rendered unit and logrotate configuration are exact-candidate artifacts with recorded SHA-256 hashes. The rendered first-start and steady-unit hashes are currently **UNKNOWN / OPEN**; what settles them is rendering against the final exact release candidate and recording the resulting filenames and SHA-256 values in the trusted-input manifest (`MTC_COMMAND_CENTER/11_TRIAGE/KVM2_PROGRAM/rebuild/manifests/TRUSTED_INPUTS.md:13-27`).
10. Resource-slice values are **UNKNOWN**. No source establishes `Slice=`, `CPUQuota=`, `MemoryMax=`, `TasksMax=`, or equivalent ceilings, and no number may be guessed. What settles this is an owner-accepted resource-slice/cgroup decision with measured rationale, exact directives (or an explicit accepted decision that none are set before the later resource gate), and incorporation into the hashed unit/profile (`36e06f92:MTC_COMMAND_CENTER/11_TRIAGE/KVM2_PHASE2_REBUILD_KIT_INVENTORY_2026-08-15.md:187-204`).
11. No first start may occur now: the owner deferred the KVM2-specific TESTNET wallet, and the decision says that open item blocks first start and forbids asking for, generating, storing, or referencing a key value (`MTC_COMMAND_CENTER/11_TRIAGE/WPI_OWNER_DECISIONS_2026-08-15_NIGHT.md:80-87`).

### Verification contract

Verification is evidence capture for later separately authorized gates; none of it is executed by this draft.

1. **Byte identity:** render the first-start template with the accepted exact SHA, record its SHA-256, and prove byte-for-byte equality between the installed unit and accepted rendered template; prove the release path and per-SHA virtual environment both name that SHA (`IBKR_PAPER_BRIDGE/deploy/linux/verify.sh:150-191`).
2. **State before first start:** prove the unit is installed, masked, inactive, not enabled, has no `[Install]` section, and the restart-enabled steady unit is absent (`IBKR_PAPER_BRIDGE/deploy/linux/verify.sh:192-225`).
3. **Directive audit:** fail unless the rendered first-start unit contains `Restart=no`, `User=mtc-bridge`, `PrivateTmp=yes`, `ProtectSystem=strict`, `NoNewPrivileges=yes`, `KillSignal=SIGTERM`, `TimeoutStopSec=45`, the throttling key, exact writable paths, exact state path, and the candidate's pinned DISARMED start mode (`2ce41e34:IBKR_PAPER_BRIDGE/deploy/linux/verify.sh:155-201`). Also fail if `After=network-online.target`, `Wants=network-online.target`, empty capability sets, or any frozen sandbox/resource-slice directive is missing from the final rendered unit (`2ce41e34:IBKR_PAPER_BRIDGE/deploy/linux/systemd/mtc-bridge-first-start.service.template:21-27,63-93`).
4. **Single first-start attempt:** under a future P4-06 authorization, capture active state, health, reconciliation, `NRestarts=0`, exactly one loopback listener, DISARMED and TESTNET-only status, exact artifact/state hashes, and no second start or retry (`MTC_COMMAND_CENTER/11_TRIAGE/KVM2_AI_LAB_AND_BRIDGE_EXECUTION_TASKS_2026-07-25.md:331-348`; `2ce41e34:IBKR_PAPER_BRIDGE/deploy/linux/COMMANDS.md:210-221`).
5. **Graceful stop:** in the separately authorized fault-injection/stop matrix, capture that the service receives SIGTERM and exits inside the frozen 45-second window without an automatic restart; the Phase-2 contract requires graceful stop and says the initial unit stops when killed (`MTC_COMMAND_CENTER/11_TRIAGE/KVM2_AI_LAB_AND_BRIDGE_EXECUTION_TASKS_2026-07-25.md:119-130`; `2ce41e34:IBKR_PAPER_BRIDGE/deploy/linux/systemd/mtc-bridge-first-start.service.template:47-56`).
6. **Restart throttling:** keep the first-start result at zero restarts. Test the steady profile only after its separate gate, using crash/kill/reboot cases to prove DISARMED recovery, reconcile gating, continuity, duplicate prevention, and the frozen interval/burst/delay behavior (`MTC_COMMAND_CENTER/11_TRIAGE/KVM2_AI_LAB_AND_BRIDGE_EXECUTION_TASKS_2026-07-25.md:119-130`; `2ce41e34:IBKR_PAPER_BRIDGE/deploy/linux/systemd/mtc-bridge-steady.service.template:7-20,24-53`).
7. **Logs:** verify ownership/mode, force rotation with the frozen configuration, prove retention/compression/copytruncate behavior, and prove rotation causes no service restart. The forced-rotation test is explicitly deferred to P4-07 and has not been run (`MTC_COMMAND_CENTER/11_TRIAGE/KVM2_PROGRAM/boundaries/NETWORK_AND_SERVICE.md:29-34`; `IBKR_PAPER_BRIDGE/deploy/linux/logrotate/mtc-bridge:1-26`).
8. **Resources:** once the resource-slice decision is frozen, verify the effective systemd properties against the hashed directives and exercise the agreed ceilings in the authorized rehearsal. Until that decision and its measurements exist, resource-limit verification remains **UNKNOWN / BLOCKED** (`36e06f92:MTC_COMMAND_CENTER/11_TRIAGE/KVM2_PHASE2_REBUILD_KIT_INVENTORY_2026-08-15.md:187-204`).

Current live KVM2 unit state, effective hardening, stop behavior, restart count, log behavior, and resource consumption: **UNKNOWN**. What settles it is the separately authorized, exact-candidate install/rehearsal/first-start evidence above; the current artifact documentation does not establish live host state, and P4-02/P4-07 define the later installed and first-start evidence boundaries (`MTC_COMMAND_CENTER/11_TRIAGE/KVM2_AI_LAB_AND_BRIDGE_EXECUTION_TASKS_2026-07-25.md:278-284,337-348`).

### Violation signature

- first-start unit active, enabled, unmasked before its separate gate, containing `[Install]`, not bound to the exact accepted SHA/venv, or accompanied by an installed steady unit (`IBKR_PAPER_BRIDGE/deploy/linux/verify.sh:150-225`);

- missing `After=`/`Wants=network-online.target`, missing SIGTERM/45-second stop contract, stop that requires premature SIGKILL, or any restart after the first-start process exits (`2ce41e34:IBKR_PAPER_BRIDGE/deploy/linux/systemd/mtc-bridge-first-start.service.template:21-27,47-56`);
- first-start `Restart` value other than exactly `Restart=no`, `NRestarts` other than zero, more than one start, any retry, or any start that is not proven DISARMED and TESTNET-only (`MTC_COMMAND_CENTER/11_TRIAGE/KVM2_AI_LAB_AND_BRIDGE_EXECUTION_TASKS_2026-07-25.md:128-130,331-348`);
