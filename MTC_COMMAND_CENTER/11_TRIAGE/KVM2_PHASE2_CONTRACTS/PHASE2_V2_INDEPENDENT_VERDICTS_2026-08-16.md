## New v2/v3 defects not filed by the v1 review

- **FS-01 requires a pre-frozen inode expectation that cannot exist for installer-created objects.** The admission record is frozen before the installer (`IDENTITY_FILESYSTEM_NETWORK_SERVICE_V2_2026-08-15.md:50-71`), while FS-01 compares observed device/inode/mount IDs with that record (`IDENTITY_FILESYSTEM_NETWORK_SERVICE_V2_2026-08-15.md:238`). **Falsification:** create the release path during installation; either its inode has no pre-install expected value and the case can only STOP, or a post-install snapshot blesses the object being checked and a wrong replacement tree can PASS.
- **NET-07 cannot detect its own transient-mutation RED fixture.** Its observation is only pre/post hashes and semantic snapshots, yet it claims an add-then-remove firewall rule must fail (`IDENTITY_FILESYSTEM_NETWORK_SERVICE_V2_2026-08-15.md:315`). **Falsification:** add a firewall rule between snapshots and remove it before the post-snapshot; endpoints are identical and the specified check PASSes.
- **SVC-05 turns a bounded observation into an unbounded no-restart claim.** It watches for 600 seconds but neither inventories timers/path units/schedulers nor limits the claim to that interval (`IDENTITY_FILESYSTEM_NETWORK_SERVICE_V2_2026-08-15.md:364-368,467`). **Falsification:** schedule an external activation for second 601; the 600-second case PASSes while an automatic restart source exists.
- **The v3 agreement check searches only the deference section, not the whole secret contract.** The prose claims no local secret-side rule may narrow/override the service authority (`SECRET_CONTRACT_HL_LIVE_ACK_V3_2026-08-16.md:21-25,33-35`), but the code extracts and tests only `$secretSection` through the next `##` heading (`SECRET_CONTRACT_HL_LIVE_ACK_V3_2026-08-16.md:69-95`). **Falsification:** add a later secret-contract section permitting an otherwise forbidden pass-through; the checker still prints PASS.
- **The v3 agreement check asserts same-candidate identity without verifying it.** The contract says mixed or unfrozen candidate identities must STOP (`SECRET_CONTRACT_HL_LIVE_ACK_V3_2026-08-16.md:33-35,101`), but the executable check accepts two arbitrary paths and records no candidate ID or document hash (`SECRET_CONTRACT_HL_LIVE_ACK_V3_2026-08-16.md:37-51`). **Falsification:** provide a service document from candidate A and a secret document from candidate B with the expected headings; the checker can PASS.
- **The normative service egress mechanism does not cover every surface it prohibits.** The prohibition includes argv, screenshots, backups, and exported evidence (`IDENTITY_FILESYSTEM_NETWORK_SERVICE_V2_2026-08-15.md:402-415`), while the egress scanner mechanism names only log/journal/diagnostic/crash/evidence manifests (`IDENTITY_FILESYSTEM_NETWORK_SERVICE_V2_2026-08-15.md:425-447`). **Falsification:** place a synthetic value-bearing record only in a backup index or screenshot surface; the four named enforcement layers can remain GREEN.
- **Recovery’s retention-denial arm has no valid-object canary or denial classification.** It treats a denied delete/retention-change attempt as sufficient (`SECRET_STATE_RECOVERY_TEARDOWN_MAINTENANCE_INCIDENT_V2_2026-08-15.md:189-195`). **Falsification:** attempt deletion of a nonexistent version with a role that can delete real versions; a not-found/invalid-target denial can be misread as the required protection.
- **Incident capability denial has no canary or exact denial class.** It requires a “safe mutation attempt” to be denied without specifying an existing target, success marker, or admissible authority-denial result (`SECRET_STATE_RECOVERY_TEARDOWN_MAINTENANCE_INCIDENT_V2_2026-08-15.md:332-334`). **Falsification:** aim the mutation at a nonexistent object while using mutation-capable credentials; target failure can be reported as capability denial.
