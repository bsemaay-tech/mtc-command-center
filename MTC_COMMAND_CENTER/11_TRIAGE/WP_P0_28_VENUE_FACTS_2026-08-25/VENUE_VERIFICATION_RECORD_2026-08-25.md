## Result and design consequences

- **16 rows VERIFIED; 4 rows UNKNOWN (`j`, `r`, `s`, `t`).** UNKNOWN is an accepted documentation outcome under the package contract when primary sources do not establish a fact.
- Old row `h` is closed at the exact safe scope: the public API says hedge mode has not been introduced and exposes one signed position size.
- Old row `j` remains UNKNOWN at its exact same-asset scope. Cross and isolated positions may coexist in one account, but no source establishes both modes simultaneously on one asset.
- Testnet subaccount-gate behavior remains UNKNOWN; an official testnet example is not proof of gate parity or exemption.
- Agent-wallet expiry is now actionable without guessing: an explicit custom expiry is supported up to 180 days. The default duration remains undocumented, so provisioning must specify and record expiry.
- Venue IP allowlisting remains UNKNOWN. The design must not claim either that it exists or that it does not.
- Actual account eligibility remains an excluded account fact. This record neither performs nor authorizes the `G6` / T0 read.
