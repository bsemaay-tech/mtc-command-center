## 1. What the round was asked to close

Codex round 5 (`SEC102_CODEX_T1_AUDIT_R5_2026-08-11.md`, **REQUEST_CHANGES**) raised one
CRITICAL, R5-F1: a pathname-expanded command word is classified as a benign leaf even when Bash
can resolve it to a recognised interpreter, so the script operand behind it is outside both
direct matchers and the independent word-conservation check — a silent no-edge RENDER
`PASS rc 0` over an unanalysed program.

The kickoff's framing is the important part, and it is correct: this was the **fourth**
command-word or prefix form found one at a time (round 4 numeric fd; round 5 named fd and
indexed assignment; round-5 audit pathname expansion). Closing a fifth in isolation would invite
a sixth. The round was therefore asked for a fixpoint, not a patch.

## 2. What was changed

The defect was never any single missing form. It was the classifier's **default**: an
unrecognised command word became `leaf`, so every form nobody had enumerated inherited "benign".
Round 6 inverts the default in `composite_pathproof.py`:

1. **`_command_word_class` is now a closed admissibility policy.** `leaf` — the only answer that
   means "benign, derives no edge" — is returned solely for a PROVEN-STATIC literal that is not a
   recognised interpreter or source builtin. Every other command word is `dynamic` or the new
   `unmodeled`, and both STOP. Assignment prefixes and reserved words are matched *before* the
   fence, so `SEEN[0]=1`, `{`, `}`, `[[`, `]]` are unaffected.
2. **`COMMAND_WORD_SUBSTITUTION_RE`** (`$`, backtick) — parameter, command and arithmetic
   expansion. Deliberately redundant with `_graph_opaque_reason`.
3. **`COMMAND_WORD_EXPANSION_RE`** (`* ? [ ] { } ~ \`) — pathname expansion, brace expansion,
   tilde expansion, backslash-constructed names. Read from the RAW word including quoted regions.
4. **`_graph_word_conservation` reports the new class** as `source_graph_unmodeled_command_word`.
5. **The reserved-word test compares the RAW word**, not its unquoted literal. Bash only treats
   `if`/`{`/`[[` as reserved when written unquoted; reading the literal promoted `"if"` to a
   reserved word and kept a command position open that Bash had already closed.
6. **Interpreter recognition now takes the basename of any command word containing a slash**,
   not only an absolute one (section 4).

No other predicate, claim, row type or output line changed. The four carried GREEN transcripts
are byte-identical to `e3906cec`.

## 4. The finding that was not in the audit

While bounding the same boundary, interpreter recognition was found to take the basename **only
for an absolute path**. So `bin/bash script.sh` and `./bash script.sh` were benign leaves while
`/bin/bash script.sh` was recognised — the same interpreter, the same operand, hidden by a
spelling. It is the identical silent-no-edge shape as R5-F1, reached through a relative path
instead of an expansion, and it was a genuine `PASS rc 0` on `e3906cec`.

It is not asserted, it is measured: `red_render_relative_interpreter.json` is an rc-level RED,
and mutation `M2` restores absolute-only recognition and returns exactly that RED to PASS while
every other RED survives.

## 5. Where this report disagrees with its own kickoff

The kickoff asked for new RED fixtures for four forms: pathname-expanded/glob, parameter
expansion, command substitution, and tilde — "each currently (`e3906cec`) leafing a hidden
interpreter/source operand into a PASS".

**That premise is false for two of the four, and the measured before-state is published instead
of the expectation.** At `e3906cec`:

* a parameter-expansion command word was already `STOP rc 3` via the command-word `dynamic`
  class (`source_graph_dynamic_command_not_modeled`);
* a command-substitution command word was already `STOP rc 3` via `_graph_opaque_reason`
  (`source_graph_nested_execution_not_modeled`).

Both fixtures were still built and are carried in the matrix as `CARRIED_STOP` controls, with
their real `e3906cec` rc printed in section 4 of the self-QA, so the claim "round 6 closed them"
is nowhere made. Three further rc-level REDs found while bounding the class — bracket-glob,
brace expansion, and the relative-path interpreter above — bring the count of genuine
`PASS → STOP` fixtures to five.

## 7. Honest residual scope

The full list is `STATUS_SEC102.md` items 1–31. The four that matter for adjudicating this round:

1. **The recognised-interpreter VOCABULARY is not closed and this round does not claim it is.**
   A proven-static literal naming an executable-capable program outside the list is still a
   benign leaf. Round 6 narrowed the residual's exposure — an unknown name can no longer be
   smuggled in behind an expansion — but narrower is not closed. It remains the production
   blocker Codex named, and `STATUS_SEC102.md` item 8 states it in those terms.
2. **The expansion character set is itself a list.** `*?[]{}~\` is one careful reading of what
   Bash expands in a command word before lookup. Option-enabled patterns (`extglob`, `globstar`)
   are built from the same characters and are covered by construction, but no proof of
   completeness across every shell option is offered.
3. **The conservative false stops grew.** `[ -f x ]`, `\cat`, `~/bin/mytool` and a subscript word
   without an `=` all STOP now. One of them was a published round-5 control at `rc 0`. These are
   refusals, not detections; the policy prefers a visible refusal to a case-by-case proof that a
   particular occurrence was safe.
4. **Three round-5 discriminators became non-discriminating**, because the round-6 fence catches
   their forms independently. Defence in depth, but it does mean the four round-5 REDs no longer
   each test exactly one mechanism.
