## R3-F1 - detection is now strictly broader than derivation

### What was wrong

`_derive_graph` matched source and interpreter commands with `SOURCE_COMMAND_RE` /
`EXEC_COMMAND_RE`, both anchored at `(?:^|[;|&()])`. It then "checked coverage" by counting
sites with a second regex built from substantially the same grammar. Any form the matcher
could not see was equally invisible to its own coverage check, so `command source "$LIB"`
produced no derived edge, no uncovered site, and a clean `R4`/`R6`/`R7` PASS.

### What round 4 does

The repair is a separation of concerns, not a wider regex:

* `_shell_words` is a new, independent lexer over the rendered bytes. It tracks quoting,
  comments, separators (`;`, `&`, `|`, `(`, `)`, newline), redirections, assignment prefixes
  and reserved words, and yields every word with a `command_position` flag.
* `_command_word_class` classifies a command-position word against a **detection
  vocabulary** that is deliberately larger than what the tool can derive: 32 interpreter
  names plus a version pattern, `source` and `.`, and 26 command wrappers.
* `_graph_word_conservation` reconciles the two sides and STOPs on every disagreement:
  `source_graph_command_word_not_modeled` (a graph-relevant command word the matcher did not
  match), `source_graph_command_wrapper_not_modeled` (any wrapper at all),
  `source_graph_dynamic_command_not_modeled` (an unresolvable command word),
  `source_graph_derived_edge_not_at_command_word` and
  `source_graph_derived_operand_not_a_shell_word` (the matcher claiming an edge from
  something the lexer does not see as a word).

The old site-count regexes are retained as a cheap extra check, but they are no longer the
coverage authority. The scanner runs only where `_graph_opaque_reason` already passed, so
here-documents and continuations still STOP first and are not tokenised as code.

One further hole was closed while here: `R7`/`F9` (`deployed_identity_binding`) used to PASS
whenever derivation was blocked, because "every derived operand" is vacuously true over an
empty set - the same Pattern-9 shape as R3-F2. They now STOP with
`deployed_identity_domain_not_derived`.

### Evidence

* 32 wrapper/blind-spot forms, each a valid shell construct that reaches another program,
  each an **executed** round-3 `PASS rc 0`: 32 killed, 0 survived.
* 5 benign controls (`echo bash`, a word containing `bash`, `2>` redirection, a leaf path
  with dots, a comment mentioning `source`): `rc 0` on both sides. The check is broad, not
  indiscriminate.
* FREEZE inherits the repair. `red_freeze_wrapped_source.json` shows the audit's exact
  point: under round-3 code the composite returned `rc 3`, but from the pinned prover
  (`F6 prover_member_stopped`) while `F3` still claimed
  `all_members_reachable_in_derived_graph` PASS. Round 4 STOPs at `F3` itself. This is
  published as a **claim-level** RED and the matrix asserts it on the reason token, not on a
  changed rc.

### Honest residual

The detection vocabulary is a list. An interpreter that is not in it, invoked at a command
position under a literal name, is classified a benign leaf and derives no edge. The surface
is far smaller than round 3's - which recognised three interpreter names at four punctuation
positions - but it is not zero, and this report does not claim it is. Executing an arbitrary
program (`./child.sh`) has never been a modelled edge kind and still is not.

## R3-F2 - every plan allocation now has a terminal constants-side disposition

### What was wrong

`_reconcile_constants` iterated the constants table only. A plan allocation the table never
mentioned produced no row and no F10 failure, while F10's PASS sentence asserted that plan
allocations and pinned constants were "one conserved value universe".

### What round 4 does

The function walks both directions. Every declared allocation gets exactly one
`ALLOCATION_RECONCILIATION` row: `RECONCILED`, or `STOP` with one of
`allocation_duplicate_blocks_reconciliation`, `constants_grammar_not_closed_for_allocation`,
`constants_value_not_literal`, `allocation_constants_value_divergence`, or the new
`allocation_absent_from_pinned_constants`. `CONSTANTS_CONSERVATION` and
`FREEZE_CONSERVATION` carry the new counters.

Audit option (1) was taken and taken **unconditionally**: there is no "can this affect
prover semantics" exemption. Deciding that a name cannot affect prover semantics requires
modelling every way a shell can reference a name - a second modelled grammar whose gaps
would reopen the Pattern-5/12 hole R3-F1 is about. Option (2) is applied to the other half:
constants-only names remain `RUNTIME_ONLY`, and the F10 claim is narrowed from
`plan_allocations_and_pinned_constants_are_one_conserved_value_universe` to
`every_plan_allocation_reconciled_and_every_pinned_constant_dispositioned`, which is exactly
what the predicate now proves.

One deliberate asymmetry, stated so it is not mistaken for an oversight: an allocation
absent from constants STOPs F10 but does **not** withhold the constants map from the prover.
Absence corrupts no value the prover re-resolves, and the analysis-unit builder independently
refuses any operand it cannot resolve from the pinned table. Every other reconciliation
failure still blocks prover invocation. This keeps
`red_freeze_constants_operand_unbound.json` driving its published
`analysis_unit_source_operand_constants_unbound` arm - which would otherwise have been
silently replaced by a prerequisite STOP, weakening a carried assertion while appearing to
pass.

### Evidence

`red_freeze_allocation_absent.json` is `green_freeze.json` with a constants table that omits
the `REMOTE_BASE` allocation. `REMOTE_BASE` is materialised into the pinned bytes at RENDER
and never referenced as `$REMOTE_BASE`, so the prover is unaffected - which is precisely why
it is the right discriminator. On identical bytes:

* round-3 code: `F5` PASS, `F6` PASS, `F10` **PASS**, composite `PASS rc 0`;
* round-4 code: `F5` PASS, `F6` PASS, `F10` **STOP**, composite `STOP rc 3`.

There is no downstream STOP to hide behind. The audit's requirement that "a downstream F5/F6
STOP is supplemental and does not close this claim defect" is met by construction.

The round-3 `F2` mutation discriminator needed one extra line in round 4 because the
allocation-side walk is a genuinely independent second comparison of the same two value
sources; both copies must be disabled before the old PASS returns.

## R3-F3 - the evidence now survives a fresh Windows checkout

### What was wrong

The repository root sets `* text=auto` and this clone sets `core.autocrlf=true`. Every
SEC102 blob was `attr/text=auto`, so a fresh Windows checkout materialises CRLF and every
byte pin breaks.

### What round 4 does

A new `MTC_COMMAND_CENTER/11_TRIAGE/WPI_PREREG_DRAFT_ROUND1/.gitattributes`, scoped to that
directory: `sec102_r1..r4_fixtures/** -text` for the pinned fixture blobs, and
`text eol=lf` for `pathscope_prover.py` and `composite_pathproof.py`. `-text` for fixtures
gives absolute byte fidelity in both directions; `text eol=lf` for the two tools fixes the
checked-out bytes to the committed LF blob while keeping both files textually diffable, so
the Lead still reviews a real diff rather than "Binary files differ".

### The scope decision, and the measurement behind it

The kickoff's example covered `sec102_r*_fixtures/**` only. That example was run as arm 2 of
the demonstration and it is **still RED**: `pathscope_prover.py` is `attr/text=auto` like
everything else and arrives at 125222 B against its pin of 122446 B, so `green_freeze.json`
fails `F4 frozen_identity_mismatch` and 10 of 40 cases fail. The two tool lines are
load-bearing, not scope creep.

No byte of `pathscope_prover.py` was modified; the entry changes only how Git materialises
it, in the direction of making its bytes match its pin. If the Lead judges this outside the
fence, the honest consequence is that R3-F3 cannot be closed with a fixtures-only attribute
and that should be recorded as an open finding rather than papered over.

### Evidence

Three arms, each a real `git clone` with `core.autocrlf=true` from a throw-away repository
that mirrors the real one (`* text=auto` at its root). Nothing was committed to
`C:\LAB\Tradingview_LAB_CLEAN`.
