## 1. The finding

`SEC102_CODEX_T1_AUDIT_R9_2026-08-12.md`, one MEDIUM, Design Defect Pattern 11 with a Pattern 9
overlay:

> the pre-launch comparison is not bound to the object PowerShell later opens … A concurrent
> process with the same principal's access can replace or modify the file in that interval; the
> child can therefore execute bytes that were never compared with the fence while `same`,
> `SCRIPT_BYTES_IDENTICAL=1`, and the published SHA-256 still describe the earlier bytes.

The round-9 wrapper created a named temporary file, wrote the fence bytes, **closed every handle**,
re-opened the *name* to read the bytes back, compared, and then launched
`powershell.exe -File <pathname>` — which resolves that name a **second** time, after the equality
decision has already been made and published. The proof was about a *name*; the sentences built on
it — *"there is no path through the wrapper on which unproven bytes are executed"* and *"the
instrument the interpreter is handed"* — were about an *object*.

Codex re-ran everything from exact bytes and reproduced all of round 9's numbers, so **no round-9
measurement is retracted**. The defect is temporal, not textual: it is the *interval* between the
proof and the interpreter's consumption of the thing proved.

## 2. Why this is a class, not an instance

Three rounds, three harness findings, one shape rotated:

| Round | What the harness never established |
|---|---|
| 7 | that the child **completed** — output was interpreted before status was known |
| 8 | that the child was handed **this document's bytes** — text I/O rewrote LF to CRLF |
| 9 | that those bytes were **still there when the interpreter opened them** |

Each repair was correct and each left the next window open, because each bound the proof one step
closer to the child without ever binding it *to* the child. So round 10 does not add a fifth test
next to the others; it removes the interval the class lives in — every window between the
verification and the interpreter's consumption — and then measures its removal.

## 3. The repair — pin the object first, verify second, hold until the child is dead

Route (A) of the kickoff, object pinning. Seven tests in execution order; 1-3 are rounds 8 and 9's,
conserved verbatim.

| # | Test | If it fails |
|---|---|---|
| 0a | Every component of the script's path — its directory and every ancestor up to the volume root — is open and held with write and delete sharing denied. | `PATH_PIN_INCOMPLETE` — no child is launched at all. |
| 0b | The object is pinned (`FILE_SHARE_READ` only) **before** it is verified, the bytes read back **through that handle** equal the fence's, and Windows refuses a write-open and a delete-open of the name with `ERROR_SHARING_VIOLATION`. | `SCRIPT_NOT_PINNED` / `SCRIPT_BYTES_MISMATCH` — the child is never launched. |
| 0c | The pathname the child will be given resolves to the pinned object — same volume serial number, same file index. | `SCRIPT_NOT_BOUND_TO_PINNED_OBJECT` — the child is never launched. |
| 1 | Process status is `0`. | `STATUS_REJECT_NONZERO_EXIT` — stdout is never read. |
| 2 | stderr is empty, or the block is named in `STDERR_CONTRACT` with a written reason. | `STATUS_REJECT_UNADJUDICATED_STDERR` — stdout is never read. |
| 4 | After the child exits, with the pin still held, the name still resolves to the pinned object and the object's bytes are still the fence's. | `SCRIPT_REBOUND_UNDER_PIN` / `SCRIPT_BYTES_CHANGED_UNDER_PIN` — stdout is never read. |
| 3 | Every published line appears in the real stdout. | `MISMATCH`. |

**Why this closes the class rather than the instance.** A rebinding needs two things: a window in
which the object can be changed, and a name that will be resolved again afterwards. The pin removes
both, and the ordering is what makes the argument complete rather than merely shorter:

* **The pin is taken before the verification, not after it.** Anything done to the file before the
  pin — by us, by a rewriter, by a partial write — is caught by the comparison that happens *after*
  the pin, because the comparison reads the pinned object. Anything after the pin is impossible.
  There is no third interval. That is the difference between shrinking a window and removing one.
* **The read-back goes through the held handle**, so the verification cannot itself be re-resolved.
  Reading it back by name is exactly the round-9 defect.
* **The name is bound to the object rather than trusted**, by volume serial number and file index,
  so the resolution the child will perform is proved to land on the object that was verified.
* **Every component of the name is pinned**, so the resolution cannot be diverted at any step:
  none of those directories can be renamed or deleted while the handles are held.
* **The exclusion is measured, not asserted.** The wrapper asks Windows for the two handles the pin
  is supposed to forbid, once per block, and requires refusal. *"I passed the right share mode"* is
  the same class of claim as round 8's *"I called the API that does not translate"*, and it is
  refused for the same reason.
* **What the lock cannot reach is detected.** A rebinding one level below the filesystem — a
  redefinition of the volume or drive letter itself — is not preventable by any share mode. The
  post-run re-resolution catches it and makes the block terminal with its stdout never
  interpreted. That residual is stated in section 5 and in `STATUS_SEC102.md` item 45, in the same
  breath as the claim, not after an audit.

Route (B), feeding the bytes to `powershell.exe -Command -` on stdin, was **not** taken. It would
have changed the contract of the published blocks: the two D026 line-ending sentinels read
`$PSCommandPath`, which does not exist without a script file, and the exit-code and here-string
parsing semantics of `-Command -` are not those of `-File`. The kickoff permits (B) only if every
published block's rc/exit semantics are conserved; they are not, so (A) it is.

## 4. Evidence

### The load-bearing measurement — D026, both directions

The window is made **deterministic rather than raced**. `HOLD` is ONE textual substitution — the
*same* one applied to both published wrappers — inserting a genuinely separate same-principal
process at the exact launch boundary: after the equality decision, before the interpreter opens the
name. It changes no gate, no comparison and no output; it only occupies the window. If the window
does not exist, the inserted process can achieve nothing, which is precisely what round 10 has to
show. The process is a harmless **rewriter**: it tries to put a different benign marker line into
the temporary script, first in place, then by replacing the directory entry, and prints what
Windows told it.

| `rebind_certified` — the document publishes the transcript only the **rewrite** produces | **ACCEPTED — the finding** | **REJECTED** |

## 5. What round 10 does NOT close

Full list in `SELF_QA_SEC102_R10.md` section 11 and `STATUS_SEC102.md` items 45-49. In short:

1. **The pin binds files and directories, not the volume.** A per-session DOS-device or mount
   redefinition is detected by the post-run re-resolution, not prevented by any share mode.
   Detection and prevention are not the same strength and are not presented as if they were.
2. **The interpreter binary is not pinned.** `powershell.exe` is resolved by name from `PATH`;
   round 10 makes no claim about its identity.
3. **A hostile local principal can stop the run.** A pre-existing writable handle makes the pin
   impossible to take, and the block is refused before the child exists. Integrity is closed;
   availability is not, and that is a different property.
4. **This is a Windows/NTFS property**, and the exclusion is measured for the two access classes
   that can rewrite an object, not for the whole access-mask space.
5. **`HOLD`, `M1`, `M2`, `M3` are mutations of the published harness**, not independent
   implementations: they show the window existed, that closing it removes the false acceptance, and
   that each gate fires — not that no other window exists anywhere.
6. **Round 9's checkout residual is carried open** (`STATUS_SEC102.md` item 41): byte identity is
   asserted against this document as it exists on disk, not against a pinned checkout. Still loud,
   still the Lead's decision, still not deferred quietly.
7. **Round 10 measures no new property of `composite_pathproof.py`.** Every classification claim is
   the round-7 claim re-executed, and the interpreter-vocabulary production-gate limitation (item
   8) is untouched and stays owner-ratified.
