## 1. The defect in one paragraph

Round 2 bound a rendered `source` operand to a plan member by **basename**. Any operand
ending in `/library.sh` bound to the member named `library`, so the prover was handed the
pinned member's bytes while the operand itself survived only as a synthetic `test -r`
readability probe. A second, independent defect let the plan's allocations and the pinned
`constants.env` name two different files for the same variable with nothing comparing them.
Either construction produced `COMPOSITE_PATHPROOF verdict=PASS rc=0` over a program whose
executed bytes were never read. Both are reproduced mechanically in
`SELF_QA_SEC102_R3.md` §3 against the exact round-2 code streamed from `35a15219`, and both
are closed here.

## 2. F1 — deployed identity replaces basename matching

**Schema.** `MEMBER_PROOF_KEYS = {"id","kind","path","deploy_path"}` at RENDER and FREEZE.
`deploy_path` is the absolute canonical POSIX path the member is deployed at and referenced
by. ALLOCATE keeps `MEMBER_KEYS = {"id","kind","path"}`, mirroring the existing
`COMPOSITE_KEYS` / `COMPOSITE_PROOF_KEYS` stage split. That choice is deliberate on two
grounds: ALLOCATE derives nothing from bytes and makes no whole-program path claim, and the
round-1 fixture tree `sec102_r1_fixtures` is outside the round-3 scope fence and therefore
must not be edited. Its seven cases are byte-unchanged and still pass.

**Binding.** `_member_for_operand` now takes only a `deploy_path -> member_id` map:

```python
def _member_for_operand(operand: str, deploy_to_id: dict[str, str]) -> str | None:
    identity = _canonical_deployed_path(operand)
    if identity is None:
        return None
    return deploy_to_id.get(identity)
```

Both round-2 basename lookups are gone — the one in `_member_for_operand` and the
basename-keyed `path_to_id` inside `SubprocessPathProver._build_analysis_unit`. A repository
grep for `basename` in `composite_pathproof.py` now returns exactly one hit, in the comment
explaining why there is no fallback.

**`..` is refused, not normalised.** `_canonical_deployed_path` accepts a value only if it is
already absolute, canonical, control-free, placeholder-free, and free of `\` and `//`. It
never collapses `..`, because collapsing `..` lexically is unsound whenever a prefix
component is a symlink. A non-canonical operand binds to nothing and STOPs.

**Unbound is STOP, not FAIL.** An operand matching no declared `deploy_path` records
`source_operand_deploy_identity_unbound` (or the `execute_source` variant) as `Verdict.STOP`,
sets `derivation_blocked`, and emits a `DERIVED_EDGE ... disposition="STOP"` row. This is the
kickoff's binding instruction and it is also the correct Pattern-1 classification: the
composite has not observed a deviant program, it has been asked to certify bytes it was never
given.

**Structural validation and conservation.** Each member's `deploy_path` is checked for
canonical absoluteness and for uniqueness across members, and each gets exactly one
`DEPLOY_IDENTITY` terminal row; `GRAPH_CONSERVATION` gained
`terminal_deployed_identity_rows`. New claims `R7` and `F9` (`deployed_identity_binding`)
carry the property, so it has its own falsifiable verdict instead of hiding inside the graph
claim.

**Evidence.** `red_freeze_deploy_identity.json` — allocation
`LIBRARY_PATH=/safe/fixture/evil/library.sh` against a member deployed at
`/safe/fixture/library.sh` — returns `STOP rc 3` under current code and `PASS rc 0` under the
exact round-2 code. Restoring a basename fallback by in-memory mutation turns it back into
`PASS rc 0`.

**The control that makes the RED mean something.**
`red_freeze_divergent_control.json` declares the real `evil/library.sh` (95 B,
`f6cc4eda…`) as a member at its own `deploy_path`. The operand then binds by exact identity,
the analysis unit carries the real child bytes, and the pinned prover resolves four
filesystem paths and one endpoint, forbidding `/etc/shadow`, `/tmp/loot` and
`exfil.example.invalid:443` at `rc 1`. The sinks were always catchable. Round 2 simply never
showed them to the prover.

## 3. F2 — one reconciled value universe

The composite resolved `$LIBRARY_PATH` from plan allocations to choose the member and then
emitted the operand raw, so the prover re-resolved the same name from `constants.env`.
Nothing compared them.

Both repair options in the kickoff were considered. Generating `constants.env` from the
allocations would need every runtime constant (`PWD`, `ROOT`, `URL`) promoted into
`allocation_requirements`, which requires a new required key on `allocation_requirements`
and would therefore break the round-1 ALLOCATE fixtures that the scope fence forbids
editing. The kickoff's second option was taken and implemented at full strength:

1. `_parse_constants` mirrors the pinned prover's `parse_constants` grammar — strip, skip
   blank and `#`, `^([A-Za-z_][A-Za-z0-9_]*)=(.*)$`, reject duplicates — and is deliberately
   **narrower**: a value that is not a plain literal is refused rather than expanded. Every
   unclassifiable form is a STOP, so a divergence cannot hide in a form the composite
   skipped.
2. Every name present in both the allocations and the constants table must be byte-equal;
   any divergence is `allocation_constants_value_divergence`, `STOP rc 3`, **before** the
   prover is invocable.
3. Every binding gets one terminal `CONSTANT` row — `RECONCILED`, `RUNTIME_ONLY` or `STOP` —
   plus a `CONSTANTS_CONSERVATION` row carrying the grammar state and the three counts. That
   is Pattern 13 applied to the value universe, not just to members.
4. Independently, `_build_analysis_unit` requires per source operand that the allocation
   resolution, the constants resolution and the member `deploy_path` are the same string.
   `analysis_unit_source_operand_constants_divergent` is unreachable while step 2 is enabled;
   it exists so that removing step 2 cannot silently reopen F2. `…_constants_unbound` is
   reachable and is driven by `red_freeze_constants_operand_unbound.json`.

New claim `F10` (`allocation_constants_reconciliation`).

**A deliberate choice, stated plainly.** The `test -r` operand is still emitted **raw**. The
alternative — substituting the resolved literal — would make divergence impossible for that
one line, but it would also be another instance of handing the prover bytes that are not the
member's own, which is the family of defect F1 belongs to. Keeping the operand raw means the
prover genuinely exercises the constants binding, and the reconciliation is load-bearing
rather than decorative. The F2 mutation in `SELF_QA_SEC102_R3.md` §4 shows exactly that: with
both comparisons disabled, the `PROVER_RECORD` row names
`/safe/fixture/somewhere/else/library.sh` and the composite returns `PASS rc 0`.

## 7. Honest residual limitations

The full list is `STATUS_SEC102.md` §"What remains". The five that matter most to a reader of
this report:

1. **The deployed identity is a declared string, not a host object.** `deploy_path` is
   compared for exact lexical equality. No host was contacted; nothing here establishes that
   the file living at that path is the pinned member. A plan that declares `deploy_path`
   falsely is not detected at this stage. Every FREEZE report now carries
   `R2_DEPLOYED_PATH_HOST_OBJECT_NOT_ESTABLISHED` as a permanent `control=false` disclosure
   so that the word "identity" in `deployed_identity_binding` cannot be read as more than it
   is.
2. Symlink resolution and mount-boundary identity remain residual R1, unchanged.
3. A constants binding the plan does not allocate is `RUNTIME_ONLY`, not a STOP. It cannot
   influence member binding — a source operand resolves only through plan allocations — and
   anything it produces is still adjudicated against the pinned allowlist. It is still a
   value the plan did not declare, and it is disclosed and counted rather than hidden.
4. FREEZE still accepts only all-shell composites with standalone direct `source` edges. The
   actual RO composite cannot PASS. Both gates are now driven by fixtures rather than
   asserted.
5. The composite's constants mirror is narrower than the prover's parser: a constant whose
   value expands another constant is refused, not modelled. Safe false stop, not coverage.

## 8. Three notes for the Lead

**(a) A line-ending durability risk — found, not fixed, out of scope fence.** This clone has
`core.autocrlf=true` under a root `.gitattributes` of `* text=auto`. Every fixture is LF in
the index and LF in the current worktree, which is why all pins match today, but a fresh
checkout or clone on Windows would materialise them as CRLF and the entire FREEZE matrix
would fail with `frozen_identity_mismatch`. The remedy is one `.gitattributes` line
(`…/sec102_r*_fixtures/** -text`), and `.gitattributes` is outside the round-3 scope fence,
so the decision is yours. The risk is **pre-existing** and applies equally to the round-2
fixture set as committed at `35a15219`. Evidence: `SELF_QA_SEC102_R3.md` §8.

**(b) Two round-2 fixtures were repointed, and one round-2 duplication was resolved.** The
new reconciliation intercepts an unparsable `constants.env` before the prover runs, so
`red_freeze_prover_grammar.json` and `red_freeze_residual.json` now drive their arms through
prover-refused allowlists instead — `allowlist_unparsable.txt` (`/**`) and
`allowlist_glob.txt` (`/safe/fix*ture/**`) respectively. Both keep their published rc and
reason token and their original semantics. As committed at `35a15219` those two plans were
**byte-identical** (both `d78d431f…5d53`), so the round-2 matrix asserted two different
tokens against one artifact; they are now two distinct artifacts with two distinct
prover-side rejections. `constants_bad.env` is retained and now drives the new
`red_freeze_constants_grammar.json`.

**(c) An ignored directory exists in both fixture trees.** A force-inclusive listing of
