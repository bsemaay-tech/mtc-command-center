> `extglob` operator family. One-or-more `+(...)`, exactly-one `@(...)` and negated `!(...)`

The scanner split each of these into three fragments (`/usr/bin/ba+`, `s`, `h`), classified all
three as proven-static benign leaves, and reported no uncovered command word and no opaque
reason — the exact shape of a false RENDER `PASS`.

## 2. Why the repair is not "add three characters"

Round 4 closed the numeric file descriptor. Round 5 closed the named descriptor and the indexed
assignment. Round 6 closed the pathname/brace/tilde/backslash forms. Round 7 was handed a
seventh class of the same shape. The regress is structural, not a run of bad luck:

> While the admission test enumerates what is FORBIDDEN, its completeness depends on the
> enumeration — and no static tool can prove an enumeration of shell operators complete.

Adding `+`, `@` and `!` would have bought exactly one round.

## 3. The repair — invert the direction of proof

A command word is admissible as a proven-static benign leaf **only when every character of the
raw, pre-expansion word token is in an explicit safe set**. Any other character — known operator,
unknown operator, or a character with no shell meaning at all — makes the word not proven-static,
so it is `unmodeled` and the stage STOPs. **The default for an unrecognised character is
refusal.** That is what makes it a fixpoint: a form nobody anticipated cannot be admitted by not
having been listed.

### The safe set is `[A-Za-z0-9._/:-]`

| Member | Why it cannot introduce dynamic resolution |
|---|---|
| `A-Z a-z 0-9` | Ordinary characters: not metacharacters, not expansion operators, not quoting. They can only spell a name. |
| `.` | Ordinary pathname character. The one-character word `.` is the source builtin, classified by `GRAPH_SOURCE_WORDS` before any word can be admitted as a leaf. |
| `_` | Ordinary pathname and NAME character. Special only as the variable `_`, which requires a `$` the set does not admit. |
| `-` | Ordinary. A leading `-` makes an option word, not an expansion. Special only inside `${var-alt}`, which requires `$` and `{`. |
| `/` | The pathname separator. Suppresses PATH, function and builtin lookup rather than introducing expansion; the classifier already takes the last pathname component of any word containing one. |
| `:` | Ordinary; the one-character word `:` is the null builtin. Special only inside `${var:-alt}`, which requires `$` and `{`. |

Excluded, each exclusion load-bearing:

* `?`, `*`, `+`, `@`, `!` — the five `extglob` operator characters. Excluding all five refuses
  the family in one rule rather than by enumeration. **This is the round-6 finding.**
* `%` — job-specification resolution when job control is enabled, an option state not modelled.
* `=` — `equals` expansion in shells that implement it; every Bash assignment word is classified
  *before* this test, so admitting `=` would buy nothing.
* `'` `"` — build a name out of quote removal rather than spelling it.
* Everything else — refused because no proof was offered that it cannot resolve.

### The kickoff's illustrative safe set does not close the finding

`KICKOFF_SEC102_BUILD_R7.md:26` suggests `[A-Za-z0-9._/+=:@%-]`. **`+` and `@` in that set are
two of the five `extglob` operators**, so under it `ba+(s)h` and `ba@(s)h` remain benign leaves.
This is not argued — it is mutation `M2` in the self-QA, which loads that exact set into the
module and shows two round-7 REDs returning to `PASS`. The implemented set is strictly smaller,
and the difference is the repair.

### One scanner change, which decides nothing

The safe set must be applied to the word Bash looks up. The scanner split at `(`, so `ba+(s)h`
reached the classifier as three fragments. Round 7 conserves an abutting `(` INTO the raw token
unless the token is a NAME, so the safe set adjudicates `ba+(` rather than `ba+`. A function
definition is the one benign construct with that shape and Bash requires a NAME for it; an
`extglob` pattern requires `?`, `*`, `+`, `@` or `!` immediately before the `(`, and no NAME ends
in one of those.

**This is not a second fence.** Mutation `M3` turns it off and kills nothing, because the safe
set already refuses `ba+`. It is published as a correctness fix to what the classifier is shown,
not as defence in depth.

## 5. What round 7 does NOT close

Full list: `STATUS_SEC102.md` items 1-36.

1. **The interpreter VOCABULARY is still a list — the production-gate blocker.** A
   safe-set-only literal naming an executable-capable program absent from
   `GRAPH_INTERPRETER_WORDS` is still a benign leaf. Rounds 6 and 7 changed *how a command word
   is admitted*; neither changed *which names are recognised*. The round-6 audit accepted this as
   a scoped limitation at this stage; that acceptance is not a closure, and round 7 does not
   claim to have narrowed it further.
2. **The safe set is a claim about Bash, as strong as one reading of the grammar.** The inversion
   means an error in that reading produces a false STOP rather than a false PASS. Better failure
   direction, not a proof.
3. **Larger conservative false stops than round 6.** `g++`, `tool@1.0`, `--opt=value`, `"bash"`,
   `'source'`, `"if"`, `2a=b`, `a-b=c`, non-ASCII names, and a non-NAME function definition all
   STOP although Bash would run them harmlessly. Six were published round-6 classifications and
   their movement is declared in advance in the grammar battery.
4. **The boundary conservation covers `(` only.** A `)` abutting a word is still a separator,
   argued from the Bash grammar rather than swept.
5. **Nothing outside the command word moved.** Operand grammar, prefix grammar, the analysis
   unit, FREEZE, the prover adapter and every host/network non-claim are unchanged from round 6.
6. Round 7 ran under **Python 3.14.2** only.
7. **The `.gitattributes` line for `sec102_r7_fixtures/**` is inert until the Lead commits it**,
   because Git reads checkout attributes from the committed tree.
