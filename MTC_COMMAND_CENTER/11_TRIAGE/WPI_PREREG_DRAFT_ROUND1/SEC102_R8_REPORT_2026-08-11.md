## 2. Why a harness defect is not a small finding

The subject of rounds 4-7 was a tool that issued a verdict over something it had never
established. Round 8's finding is the same shape in the **instrument**: the harness published a
GREEN over a run whose completion it had never established. Every carried transcript in the
self-QA — the 58-case matrix, the 1919-variant sweep, the 112-cell mutation matrix — is quoted on
that harness's authority. A verifier that can false-accept therefore devalues the evidence chain
behind it, and it is *reusable*, so the defect propagates to every future round that pastes it
forward.

It is also the cheapest possible place for a false GREEN to hide, because nothing downstream
re-checks it: the wrapper is the last thing that runs and the first thing an auditor trusts.

## 3. The repair — three tests in a fixed order, and the order is the repair

| # | Test | If it fails |
|---|---|---|
| 1 | The child's process status is `0`. | `STATUS_REJECT_NONZERO_EXIT` — **stdout is never read.** |
| 2 | The child's stderr is empty, or the block is named in `STDERR_CONTRACT` with a written reason. | `STATUS_REJECT_UNADJUDICATED_STDERR` — **stdout is never read**; the first three stderr lines are printed so the diagnostic is visible rather than swallowed. |
| 3 | Every published line appears in the real stdout (subset check). | `MISMATCH`, with the first five missing lines printed. |

A block failing (1) or (2) reaches `continue` before the comparison exists. That is what makes
this an **ordering property** rather than an extra counter: there is no path through the wrapper
on which an incomplete run's output is interpreted. Adding a third counter to the round-7 wrapper
would have satisfied the letter of the finding and left the defect's shape intact.

`RC=` and `STDERR_BYTES=` are printed for **every** block, passed or not, so the real status of
each child is *published* rather than merely tested. The wrapper's own exit is `0` only when no
block was rejected for any of the three reasons.

`STDERR_CONTRACT` is **empty**, which is its strongest form: no block published in the self-QA
may write anything to stderr. An entry must name the block and state why — and a block with an
entry must **still** return process status `0`, because an adjudicated diagnostic is not an
adjudicated failure.

Three things make this a discriminator rather than a demonstration:

1. **Neither wrapper is re-typed.** Round 7's is extracted from the `python` fence of the frozen
   `SELF_QA_SEC102_R7.md`; round 8's from the fence in `SELF_QA_SEC102_R8.md`. Each document is
   asserted to publish exactly one such fence, and the SHA-256 of the exact bytes executed is
   printed — `4ba21f81…7bca` for round 7, `391a8e20…473c` for round 8 — so a drifted or hand-typed
   instrument fails the block instead of passing it (Pattern 11).
2. **`UNREAD_STDOUT=1` on both REDs is the ordering measurement.** A wrapper that counted the
   failure but still compared the output would score `0` there and fail the case. The assertion is
   about *what was not done*, not only about the exit code.
3. **The two controls are load-bearing in the other direction.** `well_behaved_child` proves round
   8 is not a blanket reject; `published_line_absent` proves the round-7 subset comparison survives
   the repair unchanged.

The children are harmless: they print a line, exit non-zero, or write one diagnostic. No attack
fixture was authored and no sensitive body was reproduced.

### One honest note about the discriminator's own construction

The first run of the D026 block scored the clean control as `R8_REASON=MISMATCH`, because the
reason detector used a substring test and the wrapper's summary counter `MISMATCHED=0` contains
the token `MISMATCH`. The detector is now word-bounded, and the mistake is recorded in a comment
in the block rather than quietly corrected — an instrument that mis-reads its own subject is the
class of defect this round exists to punish.

## 5. What round 8 does NOT close

Full list: `STATUS_SEC102.md` items 1-40; items 37-40 are the round-8 additions.

1. **The interpreter VOCABULARY is still a list — the production-gate blocker (item 8).** Codex r7
   accepted it as an honestly disclosed production-gate decision, not as closed. Round 8 does not
   touch it and does not claim to narrow it.
2. **The harness proves each child ran to completion; it does not prove the child ran the right
   thing.** The comparison is still a SUBSET check, so a declared excerpt passes on the lines it
   publishes. Round 8 does not make the published transcripts exhaustive.
3. **The empty `STDERR_CONTRACT` is a property of this document, not a general rule.** A future
   block that legitimately writes to stderr must be adjudicated by name, and an entry never
   waives the process-status test.
4. **The outer wrapper is not a witness to its own completion.** Its status is published as
   measured by the launching shell.
5. **Round 8 measures no new property of `composite_pathproof.py`.** If the round-7 evidence was
   wrong about the module, round 8 does not detect it; it guarantees only that a block which
   *fails* can no longer be reported as reproduced.
6. Round 8 ran under **Python 3.14.2** only.
