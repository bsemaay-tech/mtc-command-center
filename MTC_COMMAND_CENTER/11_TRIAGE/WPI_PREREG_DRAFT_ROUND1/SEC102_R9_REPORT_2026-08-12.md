## 1. The finding

`SEC102_CODEX_T1_AUDIT_R8_2026-08-12.md` returned **REQUEST_CHANGES** and, in the same verdict,
closed the round-7 finding:

> **CLOSED.** The round-8 wrapper waits for the child, reads its real process status and stderr,
> and reaches `continue` on either a nonzero status or unadjudicated stderr before the stdout

> stderr-writing child can have its stdout scored as reproduced.

The finding, MEDIUM, at `SELF_QA_SEC102_R8.md:1660,1899-1900`:

> the published wrapper rewrites every LF-only PowerShell block to CRLF before execution while
> claiming that the extracted bytes are written and run byte-for-byte. It reads the Markdown
> through newline-translating text I/O and writes each temporary `.ps1` through
> `NamedTemporaryFile(..., "w", encoding="utf-8")` without disabling newline translation. On this
> Windows host, a published block containing 110 LF and zero CRLF sequences was written with 110
> CRLF sequences; the written bytes did not equal the extracted bytes.

Codex re-ran all eleven blocks from their exact bytes and obtained the same accepted results, so
**no round-8 measurement is retracted.** The defect is a false-acceptance path in a reusable
verifier, not a wrong answer already published.

## 2. Why this is the same defect one level up

Round 7's harness never established that the child **completed**. Round 8's harness never
established that the child was handed **this document's bytes**. Both are verdicts issued over
something never established — the exact shape rounds 4-7 spent four rounds removing from
`composite_pathproof.py`, now in the instrument that certifies it.

It matters because the instrument is *reusable* and *terminal*: it is the last thing that runs
and the first thing an auditor trusts, nothing downstream re-checks it, and every carried
transcript in the self-QA — the 58-case matrix, the 1919-variant sweep, the 112-cell mutation
matrix — is quoted on its authority. A verifier that certifies a byte sequence it did not run can
certify a modified, line-ending-sensitive block instead of the block on the page.

## 3. The repair — a fourth test, ahead of the other three

| # | Test | If it fails |
|---|---|---|
| 0 | The temporary script's bytes, read back from the real file, equal the fence's bytes. | `SCRIPT_BYTES_MISMATCH` — **the child is never launched.** |
| 1 | The child's process status is `0`. | `STATUS_REJECT_NONZERO_EXIT` — **stdout is never read.** |
| 2 | The child's stderr is empty, or the block is named in `STDERR_CONTRACT` with a written reason. | `STATUS_REJECT_UNADJUDICATED_STDERR` — **stdout is never read**; the first three stderr lines are printed. |
| 3 | Every published line appears in the real stdout (subset check). | `MISMATCH`, with the first five missing lines printed. |

Test 0 is round 9's repair; tests 1-3 are round 8's, **conserved verbatim**. A block failing (0)
reaches `continue` before `subprocess.run` exists, so no child is ever started over unproven
bytes; a block failing (1) or (2) reaches `continue` before the comparison exists.

The mechanism is `read_bytes` in, a bytes regex in the middle, `write_bytes` out — **but the
mechanism is not the evidence.** The evidence is that the file is read back off the disk and
compared with the fence, because *"I called the API that does not translate"* is exactly the class
of claim round 8 made and could not support. Adding the flag without the read-back would have
satisfied the letter of the finding and left the defect's shape intact.

Each block's SHA-256, byte count, LF count, CRLF count and non-ASCII count are printed for
**every** block, passed or not, so the identity and the composition of the executed instrument are
*published* rather than merely tested. The wrapper's own exit is `0` only when no block was
rejected for any of the four reasons.

Four things make this a discriminator rather than a demonstration:

1. **The two new cases are the same defect in both directions.** Row 5 is Codex's finding: round 8
   reports a block reproduced over a transcript its published bytes cannot produce. Row 6 is the
   mirror: round 8 cannot reproduce a document whose transcript is honest about its own published
   bytes. A repair that only fixed one direction would fail the other case.
2. **What decides them is a sentinel that reads its own script file and prints how many CR bytes
   it contains** — the only way to measure the bytes the interpreter was *handed* rather than the
   bytes the wrapper *intended* to hand it. It is harmless: it reads one file and prints one
   number.
3. **Neither wrapper is re-typed, and both are extracted as bytes.** Round 8's comes from the
   `python` fence of the frozen `SELF_QA_SEC102_R8.md`, round 9's from the fence in
   `SELF_QA_SEC102_R9.md`. Each document is asserted to publish exactly one such fence and the
   SHA-256 of the exact bytes executed is printed — `391a8e20…473c` for round 8 (identical to the
   digest round 8 itself published), `54ddb9e6…1ca9` for round 9. Extracting *as bytes* matters:
   reading the instrument through translating I/O would be the round-8 defect one level up.
4. **Rows 1-4 are round 8's own cases, conserved.** `CONSERVED_R8_GATES=4` measures that the
   status, stderr and subset gates all survive round 9 unchanged and that the wrapper is not a
   blanket reject.

## 5. What round 9 does NOT close

Full list: `STATUS_SEC102.md` items 1-44; items 41-44 are the round-9 additions.

1. **The interpreter VOCABULARY is still a list — the production-gate blocker (item 8).** Codex r7
   and r8 accepted it as an honestly disclosed production-gate decision, and the owner has
   ratified it as such. Round 9 does not touch it and does not claim to narrow it.
2. **Byte identity is asserted against the self-QA as it exists on disk, not against a pinned
   checkout (item 41).** The repository root sets `* text=auto` and this clone has
   `core.autocrlf=true`, so a fresh Windows clone would materialise the document with CRLF; the
   round-9 wrapper would faithfully execute *those* bytes and its assertion would still hold —
   about different bytes. Every block's `LF`, `CRLF` and SHA-256 are published so a differing
   checkout is visible rather than silent. Pinning the self-QA documents in `.gitattributes` would
   close it; **round 9 did not, because the round-9 scope fence limits `.gitattributes` to fixture
   pins.** Recorded for the Lead to decide, not deferred quietly.
3. **The proof is byte identity, not interpretation identity (item 42).** All eleven blocks are
   pure ASCII (`NONASCII=0` on every block), so nothing turns on how `powershell.exe` decodes a
   UTF-8 file with no BOM. A future non-ASCII block would be written exactly and could still be
   *decoded* differently — the unchanged Pattern-4 boundary.
4. **`M1` is a mutation, not an independent implementation (item 43).** It shows the gate is
   load-bearing; it cannot show that no other write path would defeat it.
5. **Round 8's residuals carry unchanged (items 37-40):** the comparison is still a SUBSET check,
   the empty `STDERR_CONTRACT` is a property of this document rather than a general rule, and the
   outer wrapper is not a witness to its own completion.
6. **Round 9 measures no new property of `composite_pathproof.py` (item 44).** If the round-7
   evidence was wrong about the module, round 9 does not detect it; it guarantees only that the
   block being re-executed is the block on the page and that a block which *fails* cannot be
   reported as reproduced.
7. Round 9 ran under **Python 3.14.2** only.
