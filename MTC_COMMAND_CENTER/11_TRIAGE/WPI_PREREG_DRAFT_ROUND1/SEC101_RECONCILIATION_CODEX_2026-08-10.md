# §10.1 reconciliation — RP6-P0 and RP7-WPI-RO

## Summary

The two kickoff-pinned scripts reach 20 statically bounded source-visible host-path or endpoint families: 8 are already covered by §10.1, 11 require narrow read-only extensions, and `/dev/null` must be removed rather than allowlisted because both scripts open it for writing outside the run evidence tree. Three additional families remain statically unresolvable from the block sources alone and must be closed before freeze; they are not guessed into the table. “Reach” here means a path-bearing argument, redirection, builtin test, `cd`, executable object, or endpoint visible in the frozen shell source after expansion. It does not claim to enumerate undocumented internal opens performed by pinned external binaries. The two block identities match the kickoff (`RP6-P0.sh` SHA-256 `75db028e76438bc88caba19b9c3b6411e5f573f7b6c2bd13c3883d24e4389570`; `RP7-WPI-RO.sh` SHA-256 `23e55667bec2453e21605b3551d5802b9cc28a82040789f3ead988b69aa01aad`). The supplied `PATHSCOPE_RUN_2026-08-10.log` is not a usable run record: its complete content is a session-limit message; the reported 1/37 and 4/65 diagnostics therefore serve only as kickoff/self-QA cross-checks, not proof for these bytes.

The shape grammar is sufficient for every finite result above: exact rules cover fixed files, ancestors and procfs objects; subtree rules cover the candidate and evidence trees; terminal rules preserve the B3 prohibition on descendant access. It is not sufficient to enforce the claimed read-only policy because it records only *where*, not *how*. The minimal grammar change is one access qualifier per rule—`read-exact`, `read-tree`, `read-terminal`, `read-execute-exact`, `write-tree`, and `connect`—with `<REMOTE_BASE>/**` as the only `write-tree` rule and `127.0.0.1:8790` as the only `connect` rule. No wildcard or arbitrary-prefix grammar should be added for unresolved values; freeze must reduce the trusted-Python leaf and MainPID path to exact entries.

## Written paths

Two written families exist.

1. `<REMOTE_BASE>/**` is intentional and already covered. RP7 creates capture leaves with noclobber, appends only to its own just-created leaves, copies `/proc/self/mountinfo` into run evidence, writes the normalized projection, and directs the HTTP response to `ro.status.body` (lines 127-133, 180-213, 407-425, 467-506 and 1058-1101). RP6 writes its report through the stdout descriptor already bound by the bootstrap to `EV_LOG`. This is the only write family that may remain.
2. `/dev/null` is outside the run evidence tree and is opened for writing at RP6 lines 359/361 and RP7 lines 183/624/625. It is incidental and replaceable, so it must be removed as specified in table row 18. It must not be added to §10.1.

All other table entries are read/readlink/stat/execute-only at the shell-source level. In particular, none of the `/proc` entries is opened for writing.

## Unresolvable path families

1. **RP6 inherited-PATH/partially optional-pin tool family — finding.** `P0_TOOL_PINS` defaults empty and only the Python entry is later made mandatory (lines 478-553); every other tool may remain unpinned, non-Python pins may name any absolute path (lines 505-524), and a missing pin falls back to `command -v` with `resolution=path_resolved_absolute` (lines 656-722). The resulting 12 executable paths are therefore not a finite source-derived set. **CHANGE-BLOCK:** require exactly one frozen pin for each of `stat readlink env find sha256sum systemctl ss curl timeout python3 id getent`; reject omissions; require the nine shared non-Python RP7 tools plus `id` and `getent` to equal their exact preregistered paths; require Python to equal `<WPI_FIXED_TRUSTED_PYTHON>`; delete the unpinned fallback. Only then may those exact paths be added to §10.1.
2. **RP6 venv-root prefix family — finding.** Lines 453-476 require an absolute canonical path whose basename is the candidate SHA, but do not require `/opt/mtc-bridge/venvs/<SHA>`; lines 628 and 1428-1565 then stat, canonicalize and execute that arbitrary-prefix root and its `bin/python`. **CHANGE-BLOCK:** compare `P0_VENV_ROOT` exactly with `/opt/mtc-bridge/venvs/$P0_CAND` before the first path probe. Do not widen the existing venv subtree rule.
3. **Evidence-root provenance — unresolved by either block in isolation.** RP6 only checks that `EV_DIR`/`EV_LOG` are set (lines 364-367), while RP7 proves `EV_LOG` is below `EV_DIR` (line 631) and every new leaf is below `EV_DIR` (line 182), but neither block proves that `EV_DIR` is below the frozen `<REMOTE_BASE>`. The family is already shape-covered by §10.1, so §10.1 must not be widened. Before freeze, the Stage-1 proof must analyze the complete frozen wrapper + RP0-LIB + RP0-BOOTSTRAP + block input and derive `EV_DIR`/`EV_LOG` from the exact `<REMOTE_BASE>` constant; if that composite proof remains unavailable, add an exact frozen remote-base input and an in-block descendant check rather than suppressing the prover finding.

Runtime descendants discovered by `find` are not unresolvable escape families: release results remain under the exact release subtree, and metadata results remain under the exact venv `site-packages` subtree before they are opened. Likewise, mount points and sources parsed from `/proc/self/mountinfo` are data written to the evidence projection, not later filesystem operands.
