## 1. What the round was asked to close

`SEC102_CODEX_T1_AUDIT_R4_2026-08-11.md` returned **REQUEST_CHANGES** with one required
finding, and `KICKOFF_SEC102_BUILD_R5.md` scoped this round to it:

> `composite_pathproof.py:1279` `_shell_words` preserves command position ONLY for numeric
> file-descriptor prefixes. […] a valid Bash NAMED-file-descriptor redirection prefix […] is
> emitted as a leaf word […] `SHELL_ASSIGNMENT_RE` accepts only SCALAR assignment words, so a
> valid INDEXED assignment prefix […] is also classified as a leaf and closes command position.

The repair instruction was explicitly a fail-closed principle, not a two-case patch: conserve
command position across **every** accepted assignment and redirection prefix, and **STOP on any
prefix form the scanner cannot fully model, before it can be classified as a benign leaf**.

## 4. The finding that was not in the audit

While probing the same boundary, `function foo { source lib; }` and `coproc log { source lib; }`
were found to lose the body's first command word by the identical mechanism — the bound name
was a leaf, the leaf closed the command position, and the body was never scanned. This is
measured on the committed module in `SELF_QA_SEC102_R5.md` section 2 (`function_body` and
`coproc_named_body`, `bb02c25a_SILENT_NO_EDGE=True`).

It is repaired here, with its own RED fixture (`red_render_function_body_source.json`), its own
independent mutation discriminator (M4), and two battery forms. Reporting it costs the round
nothing and hiding it would have left a defect of exactly the class the round was opened to
close.

## 5. Honest residual scope

The full list is `STATUS_SEC102.md` items 1–27. The four that matter most to a reader of this
report:

1. **The detection vocabulary is still a list.** Round 5 repaired how the scanner *reaches* a
   command word, not *which names* it recognises. An interpreter outside the 32-name vocabulary
   at a properly conserved command position is still a benign leaf. This is the surviving half
   of R3-F1 and this round did not touch it.
2. **The prefix-completeness claim is a reading of the Bash grammar, not a proof.** The
   enumerated vocabulary is stated exactly in `STATUS_SEC102.md` item 24. A prefix form that is
   neither enumerated nor resembling either modelled shape would still degrade to a leaf.
3. **`for`/`select`/`case` are argued safe, not repaired** — backed by two probes, not by
   exhaustive enumeration of reserved-word syntax.
4. **Three new conservative false stops were taken deliberately** and are disclosed rather than
   tuned away; the `raw.isdigit()` → `^[0-9]+$` narrowing is a behaviour change and is recorded
   as one.

For the Lead specifically: the `.gitattributes` scope question raised in round 4 is unchanged.
Round 5 adds one line to the same scoped file. If the Lead rejected the two tool lines that
round-4 added, that decision applies unchanged here and R3-F3 would stay open; the round-5 line
is independent of it.
