## 2. Why this is the fourth instance of one class, and what that means

| Round | What the harness never established |
|---|---|
| 7 | that the child **completed** — output was interpreted before status was known |
| 8 | that the child was handed **this document's bytes** — text I/O rewrote LF to CRLF |
| 9 | that those bytes were **still there when the interpreter opened them** |
| 10 | that nothing **re-pointed the name between the two samples that were supposed to notice** |

Each repair was correct, each was independently reproduced, and each left a subtler successor,
because each moved the proof one step closer to the child without removing the thing the class
lives in. That thing is **mutable name resolution**. `powershell.exe -File <pathname>` re-resolves
a name — through a drive letter, a DOS device, a volume mapping, a junction, a directory entry —
*after* the parent has finished deciding, and every finding since round 9 is an exploit of that one
fact. Round 10's answer was a better detector; a detector with two samples has a gap between them,
which is exactly what Codex r10 walked through.

This project has ended two regresses before, and both times the same way: RP6's line-granularity
regress ended when exact byte spans replaced a granularity that could always be sliced finer, and
SEC102's own command-word regress ended when a closed whitelist replaced a blacklist that could
always be extended by one character. Both inverted to a construction with no dimension left to
refine. Round 11 does the same thing here.

## 3. The repair — stop handing the interpreter a name

```
powershell.exe -NoProfile -NonInteractive -ExecutionPolicy Bypass
               -Command "& ([scriptblock]::Create([Console]::In.ReadToEnd()))"
```

The child compiles and runs whatever arrives on standard input. The wrapper writes it the byte
string it read **through the pinned handle** and compared with the fence — `payload is on_disk`,
the identical Python object, not a re-read and not a file. The kickoff's route **(B)**, taken
because it removes the whole layer at once; route (A) is folded in as well, because the component
chain still had to be repaired honestly (section 3.2).

**Why this closes the entire transient-rebind and mixed-chain class rather than one instance.**
A divergence between the compared bytes and the executed bytes needs two things: a name that will
be resolved again, and an interval in which the resolution can be changed. Round 10 attacked the
interval and left the name. Round 11 removes the name, and with it the interval:

* **There is no pathname in the child's argument vector.** `ARGV_PATH_SEPARATORS=0` is printed for
  every block — not one `\` or `/` in `powershell.exe`, the four switches, or the `-Command` string.
  A drive-letter remap, a DOS-device redefinition, a mount change, a junction swap and a directory
  rename are all operations on names. The child performs no name lookup for the script, so none of
  them can change what it executes. This is not a claim that they are detected; it is a claim that
  they are irrelevant, and section 13b applies one of them around the child and shows the verdict
  not move.
* **The compared object and the executed object are the same object in one process.**
  `EXEC_BUFFER_IS_PINNED_READ=1` is an identity test in the wrapper's own memory, and `EXEC_SHA256`
  is the digest of the bytes actually written to the pipe — equal to the digest of the bytes read
  through the pin, because they are the same bytes. There is no second read, so there is no second
  moment at which anything could differ.
* **No post-run sample is load-bearing.** This is the structural difference from rounds 8, 9 and
  10, each of which ended with a measurement that had to be true for the claim to hold. Round 11's
  claim holds because of how the bytes travelled, so every gate can only refuse.
* **The gate that remains load-bearing is the pre-launch byte gate**, and it is the one this
  project has already hardened twice and shown firing twice: `M1` restores round 8's translating
  write path and the block is refused before any child exists.

Route (B) was rejected in round 10 on the grounds that the published blocks' rc and
`$ErrorActionPreference` semantics might not survive `-Command -`. **That was right about
`-Command -` and wrong about the class of channel.** `powershell -Command -` reading a redirected
pipe was measured in this round to produce *no output at all* with rc 0 — a channel that would have
silently reproduced nothing. `-Command "& ([scriptblock]::Create([Console]::In.ReadToEnd()))"`
compiles the whole stream as one script block, and the contract is **proved** conserved rather than
argued: every published block is run both ways and must return the same rc, the same stderr length
and byte-identical stdout (`CHANNEL_CONTRACT_CONSERVED=10 CHANNEL_CONTRACT_SELF_EXCLUDED=1`; the
block containing the arm cannot be run inside itself, and its own conservation is measured by the
section-13c run, which executes it through the nameless channel like every other block). `exit N`,
non-empty stderr and the line-ending sentinel were measured separately and all conserve. One
contract does not: `$PSCommandPath` does not exist when there is no script file. No published block
uses it; the two D026 sentinels did, and they now carry their own text in a here-string, which
measures the same property — *the transport did not translate a newline* — in both channels and in
both directions (`script_cr_bytes=0` for LF bytes, `=2` for CRLF).

### 3.1 Every round-10 gate is conserved, and its standing is stated

The script is still written to disk, still pinned with `FILE_SHARE_READ` before it is verified,
still read back through the pin; the exclusion is still **measured** — a write-open and a
delete-open, `WINERROR=32/32`, once per block; the pathname is still bound to the pinned object;
and both are still re-measured after the child exits. What changed is what they can do: **under
round 11 none of them can admit a block.** `M3` makes that visible rather than asserted — the
rewrite succeeds, the child still executes the compared buffer, and gate 4 refuses the block anyway
with its stdout unread. A gate that can only reject conservatively is worth keeping, and it is
published as that rather than as a control that closes anything.

### 3.2 The chain is built, not counted (finding 2)

1. The work directory is pinned **first**. On NTFS an open handle anywhere in a subtree makes the
   operating system refuse to rename any ancestor of it — and the wrapper **measures** that, in
   both directions, on a throwaway subtree of its own, using the literal exclusive share mode so
   the measurement does not move when section 13b flips the wrapper's pin constant:
   `ANCESTOR_RENAME_NOTHING_HELD=PERMITTED/0`, `ANCESTOR_RENAME_DESCENDANT_HELD=DENIED/5`,
   `HELD_DIR_ENTRY_RENAME=DENIED/32`.
2. The **stable identity is read out of the held handle**, not resolved into:
   `GetFinalPathNameByHandleW` with `VOLUME_NAME_GUID` returns `\\?\Volume{…}\…` for the object the
   handle already holds. A `subst`, a drive-letter remap or a junction cannot change it.
3. The volume root is opened, and **every component below it is opened relative to its
   already-pinned parent** (`NtOpenFile`, `FILE_OPEN_REPARSE_POINT`, so a reparse point put in the
   way is opened rather than followed). Each link's object identity is recorded, each is proved
   distinct from its parent, and the descent must terminate at the pinned object. Per block, the
   script itself is then reached **relative to the pinned directory handle** and must be the pinned
   object (`LEAF_ON_PINNED_CHAIN=1`).

`CHAIN_LINKS=7 CHAIN_RELATIVE_OPENS=6 CHAIN_IDENTITIES_RECORDED=7 CHAIN_ADJACENT_PAIRS_DISTINCT=6
CHAIN_TERMINATES_AT_PINNED_DIR=1 CHAIN_COHERENT=1`, with a disposition line per link. That is what
finding 2 asked for. It is also, under round 11, **not load-bearing** — nothing the child does
resolves a component — and the report says so rather than banking it twice.

### Finding 1, reproduced against the published round-10 wrapper, then closed

The work tree of the wrapper under test is addressed through a **free drive letter** defined with
`DefineDosDevice` — no privilege; it is what `subst` does — by scoping `TMP`/`TEMP` for that child
process only. Three declared, counted substitutions route the child launch through a helper that
mirrors the current tree into a shadow root with every `.ps1` replaced by one harmless marker line,
re-points the letter at the shadow, runs the child, and restores the letter before returning. The
remap therefore begins **after** the wrapper's pre-launch sample and ends **before** its post-run
sample, as ordinary statements either side of the child. Nothing is raced.

`M4` is the control experiment and the reason the channel is the repair rather than a description

exclusion, the same chain, the same post-run samples — one constant flipped back to
`-File <pathname>`** — and the false acceptance returns.

**On the third substitution, because an auditor should not have to find it.** Under a real run the
pathname the child is given is rooted at `C:`, which *is* a per-session DOS device a same-session
actor can redefine with no privilege — that is the whole of finding 1. Re-pointing `C:` on a live
working machine, even for one child's lifetime, is not a safe thing to do, so the arm re-points a
free letter instead. `.resolve()` would canonicalise that stand-in letter straight back to `C:` and
the stand-in would stop standing in for anything; removing it makes the stand-in behave the way the
real path behaves toward the mutable device layer. It would **not** have protected the real
`C:`-rooted pathname, because it is what *produces* that pathname rather than something that makes
it immune. The substitution changes no gate, no comparison and no output, and it is declared and
counted like every other one (`R10_TRANSIENT SUBSTITUTIONS=1+1+1`, `R11_TRANSIENT
SUBSTITUTIONS=1+1+2`). This is the kickoff's sanctioned route: demonstrate the window's existence
deterministically when a live remap of the real device cannot be made safely.

## 5. What round 11 does NOT close — and the answer to the kickoff's stop-rule question

The kickoff asked: *if this construction still leaves a same-session, in-model divergence path, say
so plainly.* Here it is, plainly.

**For the script bytes, there is no such path left, and the reason is structural rather than
measured.** No name is resolved between the comparison and the execution, so there is nothing for a
same-session actor to re-point, no interval to occupy, and no sample to sit between. I could not
construct one and I do not believe one exists at this layer, which is a different and stronger
statement than the ones rounds 8, 9 and 10 were able to make.

**For the interpreter image, there is one, and it is not closed.** `powershell.exe` is still
located by name from `PATH`. A same-session actor who can change what that name resolves to can
arrange for a different program to receive the bytes, and that program can print any transcript,
including a published one. Round 11 **neither prevents nor detects this**, and it is not dressed as
either. It is outside the model every round of this work has used — *"were the compared bytes the
bytes that were executed"*, not *"which program executed them"*, which is why rounds 7-10 all
carried it as an explicit non-claim (round-10 residual 2). But it has the same accepted-divergence
*shape* as R9-F1, R10-F1 and R10-F2, and pretending otherwise is exactly the Pattern-9 move this
project keeps punishing. So: **the Lead should treat this as a disclosed residual, not as a
closed one.** Closing it would require consuming the image without name resolution too — creating a
section from an already-open image handle and launching from that — which is a substantially larger
change than this round's scope fence permits and is not, in my judgement, worth a round 12 on its
own. My recommendation is accept-with-disclosure on item 51.

The other residuals, in short (full list in `SELF_QA_SEC102_R11.md` section 11 and
`STATUS_SEC102.md` items 1-52):

1. **The conserved round-10 gates are one-directional now.** They can refuse; they cannot admit.
   Stated as a demotion, not banked as a second control.
2. **The chain is proved coherent and is not load-bearing.** Built because round 10 claimed it
   without building it, not because the execution depends on it.
3. **The NTFS ancestor freeze is measured on this wrapper's own subtree** and generalised to
   `C:\Users` by the I/O-manager rule, not by measuring those directories. Stated as an inference.
4. **`HOLD`, `TRANSIENT`, `M1`-`M4` are mutations of the published harness**, not independent
   implementations. They show the window existed, that the construction removes the false
   acceptance, and that every conserved gate fires — not that no other window exists anywhere.
5. **A hostile local principal can still stop the run** (integrity closed, availability not), and
   the run holds read handles from the volume root down to its temporary directory for its
   duration, which denies other processes renames and deletes there. Named, not left to be noticed.
6. **This is a Windows/NTFS property**, measured on this host, on this volume, under Python 3.14.2.
7. **Round 9's checkout residual is carried open** (`STATUS_SEC102.md` item 41): byte identity is
   asserted against this document as it exists on disk, not against a pinned checkout. Still loud,
   still the Lead's decision.
8. **Round 11 measures no new property of `composite_pathproof.py`.** Every classification claim is
   the round-7 claim re-executed, and the interpreter-vocabulary production-gate limitation (item
   8) is untouched and stays owner-ratified.
