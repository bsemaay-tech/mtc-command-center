# Concrete API supplement for counterpart writers
Research-only2.1.0 candidate, no existing schema edits. This is a Lead engineering decision supplement to INTERFACE_FREEZE.md, frozen before code. Existing formal P012 ExecutionEconomics.resolve signature and EconomicTransition stay unchanged.

1. In shared_risk_calculator.py add SizingProposal (frozen dataclass) with sizing_method,allocation_policy_version,proposed_qty,notional,realised_money_at_risk (Decimal values). Add resolve_sizing_request(*,request,account_size,entry_price,stop_price,contract_multiplier,metadata,caps,existing_gross_notional,observed_volatility=None,observed_estimator_id=None)->SizingProposal. request is existing SizingRequest; metadata existing PackageMetadata; caps existing AllocationPolicyCaps. Preserve old functions/dataclasses behavior. Accept explicitly known zero minima only in this new dispatcher when authoritative metadata allows them; None remains refused. If shared StrategyPackage cannot represent a production metadata rule, refuse that binding rather than change its schema or invent a scalar. One effective quantity after step-floor, before all full-rejection caps. Stop-risk remains required when applicable. Counterpart may choose private helper names only; these exported names stay fixed.

2. NEW core/p020_economics.py exports P020Binding frozen dataclass with bound_intent:BoundSizingIntent, snapshot:AccountSnapshot, allocation_policy:AllocationPolicy, risk_bucket:RiskBucket, caps:AllocationPolicyCaps, instrument_metadata_hash:str, expected_instrument_record_digest:str, expected_package_hash:str, observed_volatility:Decimal|None=None, observed_estimator_id:str|None=None. The three expected identities are frozen research-profile inputs, not a replacement hash recipe or caller assertion of final acceptance. A binding request must match these separately named tokens; raw record digest and package metadata hash are distinct. The research profile builds instrument_metadata_hash from canonical_json of the existing shared InstrumentMetadata, including contract_version; validates comparable authoritative instrument quantities/tick/multiplier against the record before construction. Full StrategyPackage/source ownership/production admission remains a later acceptance fence; never claim those from these constructor fields alone.
P020EconomicsAdapter(binding:P020Binding|None=None) extends the existing version-specific interface. OPEN requires binding; exits/funding use existing corrected semantics without re-sizing. Before OPEN, check snapshot digest, equity/exposure against actual supplied state/profile, binding versions, bucket identity, request semantic2.1.0/direction/time and expected identities. P020 binding must be immutable and no mutation leaks into caller records. Use shared compute_account_snapshot_id when identity lane is ready; no copied permanent identity function. No monkeypatch of old _size_quantity. Reuse old fee/price/stop/exit/funding helpers through composition or subclassing, preserving old files. New OPEN builds its transition once with the new shared dispatcher.

Snapshot producer excludes snapshot_id and preserves other shared serializer behavior; validate finite fields. Public snapshot(taken_at)->AccountSnapshot, resolve_and_apply(intent,market,records,*,binding=None,decision_slot='primary')->EconomicTransition. Caller supplied binding snapshot must equal actual current portfolio snapshot and identities; the primary slot is fixed in the research profile, not a per-retry usernonce. The portfolio owns positions/cash/lifecycle counters. Its initial slice may support one open instrument per account only IF it explicitly refuses an additional instrument/position and reports that limitation; do not pretend a single-position map proves general multi-instrument portfolio support. Account-wide gross-exposure checks still consume actual current exposure. Same-bar rejection latches persist independently of changed intent/snapshot IDs. No quantity computation in portfolio.

Consumer adaptation follows the finalized profile shape once integration writer reports it; do not invent a second profile schema in each consumer.
