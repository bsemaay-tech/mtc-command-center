## 4. Ownership / authenticity evidence (intake "unmet check 1")
The intake demands "separate authentic evidence of venue origin, account ownership/control, actual order/fill association, and capture completeness" (`REAL_OBSERVATION_INTAKE.md` fee package item 4) without prescribing a method. Proposal for the reviewers to accept or refine:
- **Ownership/control:** the owner signs one plain-text message with the account wallet (EIP-191 `personal_sign`: no gas, no funds moved, nothing sent to the venue). The Hyperliquid app has no message-signing screen, and third-party signing sites are a phishing risk, so the Lead builds a tiny LOCAL page (one HTML file opened from disk, no network, reviewed with the capture tool) that asks the owner's wallet extension to sign the fixed text `MTC P012 Path 1 — account <address> — capture run <run_id> — <UTC date>`; the wallet shows the text, the owner clicks Sign, the page displays the signature to copy; the capture tool verifies offline that it recovers the address (`eth_account`, already in the lock). Alternative (weaker, no tooling): owner attestation only.
- **Venue origin + completeness:** the capture tool records the full HTTP exchange (request, response bytes, timestamps, endpoint URL, `MAINNET_API_URL` constant) and re-queries twice; the fill `oid`/`tid`/`hash` set must be identical across the re-queries.
- **Order/fill association:** the owner's screen (read by the Lead during the session) shows the same `oid`s the API returns; screenshots are kept.
