# Factual handoff — G7

Before stopping, read selected OUTPUTS. Update the selected stage's existing HANDOFF, not a new
session journal. Factual progress and blockers are allowed before acceptance; only the Lead may
record ACCEPTED after the required review contract and independent evidence are satisfied.

Record a dated section with branch/worktree and exact refs, actual outcome, changed scope,
implemented/verified/accepted status, command/cwd/environment and evidence links, remaining
limitations and dependencies. A failed command stays failed. Label a docs candidate or partial
package plainly; neither local commits nor reported reviews establish whole-package acceptance.

Keep HANDOFF <=4096 bytes. Before material shortening, preserve superseded bytes in the existing
history directory and link them as historical, not current instructions. Sticky owner decisions
go to root DECISIONS; stable facts/working-set/lane records change only when the underlying fact
changes. Retired SESSION_LOG and historical GLOBAL_HANDOFF/NEXT_STEPS are not append targets.

Before releasing ownership, reconcile current master, branch and durable tracker; unknown
ownership/live dependencies block takeover or cleanup. Ordinary local commits follow AUTONOMY;
push/PR/merge stay separate. Never imply live readiness from workflow completion.

Close with owner-readable actual result and limits, exact practical NEXT ACTION, and WAITING FOR
OWNER (Nothing if authorized work can proceed). If blocked, name the real missing evidence or
material permission; routine repair checkpoints are not owner gates.
