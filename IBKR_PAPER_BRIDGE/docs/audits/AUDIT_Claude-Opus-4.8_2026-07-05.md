# Audit — IBKR Paper Bridge design
Model: Claude Opus 4.8 (claude-opus-4-8) | Date: 2026-07-05 | Docs commit: c2c3bbb0

## 1. Summary verdict

**Ship-with-fixes.** The architecture is sound and unusually disciplined — the "LLM narrows only,
never widens" boundary is genuinely enforceable by construction (parse-into-two-models, no code
path to qty/price), and the mock-first build order is correct. But three classes of problem must
be fixed before P2: (a) a **money-safety hole** — the live-port lock only knows TWS 7496 and misses
IB Gateway's live port 4001; (b) the **bar clock** — `keepUpToDate` last-bar-of-session detection,
RTH 1h alignment, and delayed-data cadence quietly corrupt every downstream metric (signals,
slippage, parity); (c) an **internal contradiction** — consecutive-loss auto-DISARM + *manual*
re-arm makes the P2 "≥10 days unattended" criterion unachievable. Data model can't cleanly
reconstruct PREREG §5 per-trade fields (no `decision_id` on `trades`). The 1-day budget is
aspirational (~12.25h of estimates, zero slack; dashboard + IBKRBroker under-costed).

MEDIUM = wrong/ambiguous spec, builder will guess; LOW = polish.

## 3. Dimension notes

**A. Broker/API correctness** — Weakest dimension. The `keepUpToDate` bar-close model (F-03), delayed-data streaming assumption (F-04), RTH 1h alignment (F-05), re-subscribe-on-reconnect (F-06), and TWS order-precaution popups (F-07) are all real ib_async/TWS behaviors the spec glosses. `reqMarketDataType(3)` before requests: correct. bracket/OCA and modify-stop-for-trail: mechanically fine. clientId "collision = startup error not retry" (§6.1) conflicts with reconnect: a *transient* same-id busy on reconnect must retry, not hard-fail — distinguish startup vs reconnect.

**B. State machine & concurrency** — DISARMED/ARMED/KILLED is clean; the per-trade lifecycle is good. Holes are in the async interleaving: post-await re-check (F-02), reconciler grace (F-11), partial-fill+DISARM (F-23), foreign-position adoption (F-17), and undefined flip sequencing (close-fill-before-open vs both-at-once — spec doesn't say; a partial close breaks flip sizing).

**C. Risk engine math** — Formula is standard fixed-fractional and mostly complete. Gaps: zero/tiny stop guard (F-14), delayed unrealized + day-boundary tz (F-15), cooldown/exit-reason ambiguity (F-16), and **missing buying-power/margin check** — qty is clamped to 20% notional but never checked against account buying power → avoidable rejects. No commission/slippage buffer in sizing. Currency mismatch (equity vs USD price) unhandled (low risk on USD paper).

**D. LLM gate** — Strongest dimension by design. Narrowing-only is truly enforced (intersect + parse-into-model + no code path to order fields). Prompt-injection surface via Grok is inherently low-impact: worst case an injection forces NO_TRADE/LONG_ONLY (denial), never a bigger/new order — this is the design's best property, keep it. Residual: unclamped TTL (F-20), no confidence gate on the veto path (only regime has `min_confidence`), and veto adds a Claude call + loop-block on every signal (F-02).

**E. Data & persistence** — Schema can *almost* compute PREREG §5 but the `trades↔decisions` link is missing (F-09) — the single most important audit-trail gap. Plus equity PK/run_id (F-18), no bars table (F-19), missing indices, and UTC normalization discipline. `decisions.payload_json` as the reasoning chain is a good idea; it just needs a clean key back from `trades`.

**F. Dashboard & API** — Spec is buildable except: nonce blocking KILL (F-10, safety), WS reconnect resync (missed fills/DISARM while socket was down → stale UI; no sequence numbers or re-fetch-on-reconnect), and Gate Monitor staleness when the last event was NO_SIGNAL (card shows hours-old gates without a "stale" marker). `/api/bars` sourcing unspecified (F-19).

**G. Security** — Live double-lock has the 4001 hole (F-01, the headline finding). Otherwise the localhost + env-secrets + git-ignored `data/` posture is appropriate for v1. `raw_response` storage of Grok output is fine (data, not executed). Nonce readability (F-25) is a v1.1/tunnel concern, not v1.

**H. PREREG soundness** — Gates are well-sequenced and Barış-approval-gated (good governance). But three pre-registered rules are not cleanly measurable as written: parity assumes unverified bar identity (F-12); the 25 bps slippage rule is contaminated by delayed-data + paper-fill simulation, so it measures noise, not execution quality — document that paper+delayed slippage is uninterpretable; veto-precision review ("no measurable harm avoided") has no counterfactual method and near-zero sample size in 30 days. P2 "unattended" contradicts §7 auto-DISARM+manual-rearm (F-08).

**I. Build plan feasibility** — Order (mock-first, IBKR at task 8) is exactly right and P0-gated on Barış. But the day is over-packed (F-13), golden-parity risks circularity (F-21), acceptance criteria skip the concurrency/OCA hard parts (F-24), and there is **no task** for the TWS API setup checklist (F-07) that P0 depends on. Task 4's golden generation also quietly re-introduces a QuantLens dependency the bridge is meant to be independent from — fine at build time, but call it out.

## 4. Improvements (≥5)

1. **Default-deny port lock.** *What:* refuse any broker port not in an explicit paper allow-list `{7497, 4002}` unless `IBKR_LIVE_ACK` is set; drop the single-value 7496 check. *Why:* closes F-01, the money-safety hole, and is future-proof against custom ports. *Cost:* S. *Amends:* §11.1, §6.1. *Fits:* **v1** (few lines).

2. **Deterministic bar-close boundary.** *What:* stop trusting `keepUpToDate` object-appearance; drive `on_bar_closed` from `hasNewBar` **plus** a session-end timer that force-closes the 16:00 ET bar, or aggregate 5 s `reqRealTimeBars`. *Why:* fixes F-03/F-04 last-bar and delayed-cadence problems that corrupt signals/slippage/parity. *Cost:* M. *Amends:* §6.1. *Fits:* **v1** (core correctness).

3. **Link trades to their decision chain.** *What:* add `decision_id` FK + `signal_ts/decision_ts/submit_ts/fill_ts/llm_directive_at_entry` to `trades`; add indices; add `run_id` to `equity`. *Why:* makes PREREG §5 metrics + Journal drawer + `/api/decisions?trade_id=` actually work (F-09/F-18). *Cost:* S. *Amends:* §7, §8. *Fits:* **v1**.

4. **Post-await state gate + preemptive KILL.** *What:* re-read ARMED/position/kill flags right before `submit`; abort if changed; run KILL/DISARM on their own path that short-circuits any in-flight decision. *Why:* prevents submitting into a disarmed/killed/already-positioned state (F-02) and guarantees kill responsiveness. *Cost:* M. *Amends:* §5, §6.5. *Fits:* **v1**.

5. **Reconciler pending-grace state.** *What:* mark freshly-submitted orders PENDING; exclude from reconcile until age > 2× interval; only flatten on settled naked positions traceable to app orderRefs. *Why:* stops wrongful flatten from in-flight races (F-11/F-17). *Cost:* S. *Amends:* §6.5. *Fits:* **v1**.

6. **Unattended-safe loss governor.** *What:* configurable `on_consecutive_loss: disarm | pause_auto_rearm(after cooldown, max_rearms/day)`; scope the counter to distinct-signal losers, not trail scratches. *Why:* resolves the P2-unattended vs auto-DISARM contradiction (F-08). *Cost:* S. *Amends:* §6.3, PREREG §7. *Fits:* **v1** (config + a counter).

7. **TWS/Gateway setup checklist + P0 popup check.** *What:* a `docs/04_TWS_SETUP.md` (enable API, socket port, bypass order precautions, trusted 127.0.0.1, master client id, auto-restart) and a P0 assertion that a bracket transmits with no modal. *Why:* removes the #1 silent-freeze cause for unattended runs (F-07). *Cost:* S. *Amends:* docs, PREREG P0. *Fits:* **v1**.

8. **Persist bars + two-stage parity.** *What:* a `bars` table; serve `/api/bars` and parity from it; gate parity on bar-identity before signal-identity. *Why:* forensics + fixes F-12/F-19. *Cost:* S–M. *Amends:* §7, §8, PREREG §6. *Fits:* **v1.1**.

## 5. Feature ideas (≥5)

1. **Live parity gauge.** Continuously replay the offline engine on the same live bars and render a rolling parity % on the dashboard. *Value:* turns the PREREG parity rule into an early-warning gauge — plumbing drift shows instantly instead of at P3 post-mortem. *Cost:* M. *Phase:* v1.1. *Risk:* extra CPU per bar (negligible at 1h).

2. **Real-data shadow mode.** Connect to TWS for *real* bars but route all orders to MockBroker — a real-market dry-run before arming paper. *Value:* de-risks the arm decision; catches data issues without any order. *Cost:* S (MockBroker exists; just a routing switch). *Phase:* v1.1. *Risk:* mode confusion — needs a loud UI pill.

3. **Counterfactual veto ledger.** When the LLM vetoes, log the trade that *would* have fired and track its simulated P&L. *Value:* makes the PREREG veto-precision review computable (harm-avoided = counterfactual loss avoided). *Cost:* M. *Phase:* v1.1. *Risk:* counterfactual fills are estimates — label as such.

4. **Deterministic event gate (earnings/FOMC).** A static CSV of AAPL earnings + FOMC/CPI dates → hard NO_TRADE windows, independent of the LLM. *Value:* removes reliance on Grok for the highest-risk blackout windows; deterministic and auditable. *Cost:* M (data source is the work). *Phase:* v1.1 (already flagged in §13; propose the CSV MVP). *Risk:* stale calendar — needs an update reminder.

5. **Dead-man's-switch.** If dashboard heartbeat is lost for N min while ARMED with an open position lacking a working SL, auto-flatten. *Value:* bounds worst-case unattended exposure if the process/UI wedges. *Cost:* S–M. *Phase:* v2. *Risk:* false trigger on a network blip — tune N, require the *no-SL* condition too.

6. **One-click decision-chain export.** Export a trade's full decision payloads to shareable JSON/markdown for the MCC `11_TRIAGE/` report. *Value:* closes the P3 "results feed back to MCC as a written report" loop with real artifacts. *Cost:* S. *Phase:* v1.1. *Risk:* none.

7. **Order-type A/B on paper.** Alternate entries between MKT and marketable-LMT to empirically test the 25 bps slippage rule's sensitivity to order type (paper only). *Value:* tells you whether the slippage rule is measuring order type or noise before any live talk. *Cost:* S. *Phase:* v2. *Risk:* halves per-type sample size — only meaningful with enough trades.

## 6. Top-3 verdict

**1 — Close the live-port hole (F-01).** This tool's founding promise is "paper first, real money only behind a deliberate double-lock." IB Gateway — the standard unattended setup — runs live on 4001, which the current lock waves straight through. A single mis-set port in `bridge.yaml` (PUT-editable at runtime) connects real money with none of the gates firing. It is a few lines to switch from block-list to allow-list, and until it's done every other safety claim in §11 rests on a false floor. This is the one finding that is literally about not losing real money by accident, so it ranks first.

**2 — Fix the bar clock and parity bar-identity (F-03 / F-05 / F-12).** The entire stated objective is *plumbing validation* — proving signal→risk→order→fill→log is faithful. Every metric that proof depends on (signal timing, slippage vs bar-close, ≥95% parity) is computed off the bar boundary. `keepUpToDate` never closes the last session bar, delayed data shifts the close ~15 min, RTH 1h bars don't tile the session, and parity silently assumes bar identity that isn't checked. Get this wrong and the dashboard shows green while measuring the wrong thing — the worst failure mode for a validation tool. Fix the close boundary and gate parity on bar-identity-first.

**3 — Resolve unattended-vs-auto-DISARM and add the post-await state gate (F-08 / F-02).** P2 is the whole point — ten unattended days on paper. As written, a trailing strategy's normal chop trips `max_consecutive_losses` into an auto-DISARM that only a human can clear, so P2 can't complete as specified; and because the decision chain awaits the LLM without re-checking state, an order can land *after* DISARM/KILL or after the position already changed. Make the loss governor auto-re-arm under a bounded policy and re-read state immediately before submit. Without these two, P2 either stalls or acts on stale intent — and both are things you want fixed on paper, not discovered on the way to live.
